# 视频结构与风格复刻

## 参考与取舍

| 项目与已读取来源 | 方法 | 本项目采用的部分 |
| --- | --- | --- |
| [VACE](https://github.com/ali-vilab/VACE)，README、`vace_pipeline.py`、`configs/video_preproccess.py` | 区分参考图生成、视频编辑、遮罩编辑；预处理深度、光流、姿态等控制信号 | 参考视频约束动作与时序属于画面编辑，不能把它等同于语义结构复刻。生成请求必须按模式选择参考资料。 |
| [VideoDirectorGPT](https://github.com/HL-hanlin/VideoDirectorGPT)，README 的两阶段规划与实体一致性说明 | 先写场景、实体、布局和一致性分组，再交给 Layout2Vid | 在生成前保存可核对的全片风格、原镜头作用和目标逐镜动作；同一实体共用专用素材及定妆图。该仓库展示研究方法，不据此宣称本项目已经接入 Layout2Vid。 |
| [ComfyUI-WanVideoWrapper](https://github.com/kijai/ComfyUI-WanVideoWrapper)，README、节点与工作流目录 | 按模型与任务拆分参考、动作、相机控制和采样能力 | 用当前模型能力选择请求；不把任意 API 模型都宣传为支持深度、姿态或遮罩约束。 |
| [Remotion](https://github.com/remotion-dev/remotion)，`packages/core/src/Sequence.tsx` | 用明确的时间区间组织媒体序列 | 保留本项目毫秒时间线与真实媒体时长校验；不新增第二套剪辑引擎。 |

参考示例把摇椅广告转换成扶手椅广告：保留人物入座、使用情境、细节展示和收尾的表达组织，但将摇动、触摸靠背等动作改成适合新椅子的动作。结构复刻应保留镜头作用及节奏，并允许主体、动作与具体展示部件变化。

本项目不下载或部署这些研究模型，不新增 GPU 服务，也不复制其代码。使用现有文本 / 图片 / 视频模型渠道、任务持久化、素材归属和候选验收流程。

## 目标边界

- 换元素：沿用原片画面动作、机位和切点，向视频模型传入参考片段。
- 结构复刻：分析原镜头的叙事作用；保留镜头顺序与原区间，生成适合目标主体的动作和新文案。原视频只用于分析，不进入视频生成请求。
- 风格复刻：从关键帧与拆解提取色彩、布光、材质质感、构图、运镜与剪辑语言；根据目标主体重新组织镜头，使用独立目标时长。原人物、品牌和商品不是身份参考。

页面只协调模式、资料、模型选择及方案预览。`lib/remake` 定义方案校验、输入快照、模式约束与生成提示词。规划服务保存任务标识和冻结输入，查询原任务恢复；作品服务继续使用修订号比较交换。后端校验新增合同、资源和任务归属。

规划前保存输入与幂等操作标识，只把实际请求的 SHA-256 摘要写入作品，不持久化渠道凭据。提交响应丢失时只能重放相同请求；渠道或参数变化时要求恢复原设置，并保留任务记录。已有任务标识时直接查询，不重新提交。另一窗口已经保存任务时拒绝覆盖；配方保存仅更新改编要求和目标时长，不覆盖规划服务的方案与任务。旧方案和未结束任务的冻结素材继续参与资源引用与归属检查。

## 生成与验收

1. 原片拆解与关键帧作为分析依据；资料不完整时提示补全。
2. 上传目标主体、人物与场景，填写事实及改编要求。
3. 生成参考方案，展示原镜头作用、目标动作、时长及风格资料。
4. 用户应用方案后才能生成；修改关键资料使旧方案失效。
5. 定妆与候选继续需要确认，未知时长、配音溢出、旧配方候选与未确认候选阻止交付。

结构模式按原时间轴核对。风格模式的镜头组织与时长独立，展示参考片与新片时不能宣称逐帧对齐，也不能套用原片声音或自动导出同步对比。

## 能力边界

通用 API 通过参考图和提示词表达风格及动作，无法保证像专用深度 / 姿态控制模型那样精确。真实商品、人物身份、包装文字、声音和跨镜一致性仍须模型实机验收。结构与风格方案的自动校验验证合同及引用，不将其包装成自动画面质量评分。
