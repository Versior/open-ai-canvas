# 服饰与人物视频工作台

视频首页原来的“模特换装、人物与形象、印花素材”打开的是图片工作台。图片任务后的图生展示无法证明原视频已换装、换脸或换印花。现在三个入口分别进入独立视频工作台；图片换装、姿态迁移、换脸和印花提取仍在生图台。

## 输入与实际输出

| 工具 | 输入 | 每个生成单元的目标 |
| --- | --- | --- |
| 视频换装 | 原视频 + 一张服装图 | 保留人物、动作和场景，替换指定上身、下身或连衣裙 |
| 一人多套视频 | 原视频 + 2–6 张服装图 | 每款独立出片，共用同一原动作，不在一条片中混款 |
| 多模特同款视频 | 原视频 + 2–6 张人物图 + 一张服装图 | 每位人物独立出片，身份图与服装图分开引用 |
| 视频换脸 | 原视频 + 一张身份图 | 修改面部身份，保留头发、身体、动作和机位 |
| 视频换头 | 原视频 + 一张身份图 | 修改头部与发型，匹配颈部、朝向、光线和遮挡 |
| 动作参考视频 | 动作视频 + 一张人物或角色图 | 外观依据人物图，运动依据动作视频 |
| 印花上身视频 | 原视频 + 一张平面图案 | 保留衣物材质与版型，图案随布面、褶皱和遮挡变化 |
| 模特展示视频 | 1–6 张已确认的模特图 | 每张作为首帧独立拍摄展示片段；不提交原视频 |

原视频支持 MP4/MOV，前端入口上限 200MB，超过普通上传阈值复用分片上传。处理范围为 4–30 秒整数时长，最终可选值受模型时长、视频参考上限和输出参数共同限制。起点支持十分之一秒。每次生成前保存当前素材、选段、模型、画幅、声音和提示词，素材必须已上传且属于当前账号。

原片流程先切出所选范围，模型仅接收切出的片段与当前单元图片。参考图、原片视频和图生展示首帧采用不同输入角色。不能接收视频或图片参考的模型会被禁用，不靠模型名字猜能力，也不会降级成图片编辑。

## 项目与竞品研究

以下结论来自 2026-11-09 读取的官方 README、推理源码与接口 schema。服务商能力和参数会变化，新增渠道应再次核对，不能把项目演示当作当前工作台已集成该引擎。

| 来源 | 查证的实际机制 | 对本工作台的影响 |
| --- | --- | --- |
| [MagicTryOn](https://github.com/vivoCameraResearch/Magic-TryOn) | 自定义推理准备衣物描述、线图、逐帧人体遮罩、agnostic 与 DensePose，以视频扩散模型处理时序 | 视频换装必须接收原片与衣物条件，不能用单张换装或图生展示替代 |
| [CatV2TON](https://github.com/Zheng-Chong/CatV2TON) | `eval_video_try_on.py` 将连续帧与服装条件送入视频推理，处理跨片段连续性 | 多款服装分别生成；检查首、中、末帧及遮挡后是否保持同款 |
| [ViViD](https://github.com/alibaba-yuanjing-aigclab/ViViD) | 原片、衣物/衣物 mask、agnostic 视频及 mask、DensePose 是不同输入 | 印花提取仍属于图片；印花上身视频需要明确布面运动、透视与遮挡 |
| [FaceFusion 换脸源码](https://github.com/facefusion/facefusion/blob/master/facefusion/processors/modules/face_swapper/core.py) | 聚合参考身份、按人脸关键点对齐裁切，组合 box、occlusion、area、region mask，再贴回视频帧 | 换脸与换头是两种编辑范围；通用视频生成不能冒称部署了人脸对齐和遮罩引擎 |
| [Wan2.2 Animate 预处理](https://github.com/Wan-Video/Wan2.2/blob/main/wan/modules/animate/preprocess/preprocess_data.py) | 驱动视频与参考图分开输入；replacement 使用 SAM2，animation 可 retarget。推理读取 `src_pose.mp4`、`src_face.mp4`；替换另读背景与 mask | 动作迁移与原视频人物替换应分清身份、服装、场景、运动的来源 |
| [Kling 2.6 Motion Control 接口](https://fal.ai/models/fal-ai/kling-video/v2.6/standard/motion-control/api) | `image_url` + `video_url`，`character_orientation` 决定图/视频方向，支持原声策略 | 原视频能力、参考时长和声音策略需要共同约束；不同视频模型不能共用未经校验的参数 |
| [Kling O1 视频编辑接口](https://fal.ai/models/fal-ai/kling-video/o1/video-to-video/edit/api) | `video_url` 与 `image_urls`/`elements`，提示词显式引用图片和主体，输入视频限制 3–10 秒 | 每个单元送明确引用，先切片再提交，不把 30 秒输入送给只支持 10 秒参考的模型 |
| [Runway 官方 OpenAPI](https://docs.dev.runwayml.com/openapi.json) | `/v1/video_to_video` 的 `aleph2` 用 `videoUri`、可选 `promptText` 和最多五个定时 `keyframes`；请求按模型分支定义 | 真正的视频编辑与普通图生视频是独立合同；定时关键帧属于专用渠道能力，当前不能伪装成已经支持 |

MagicTryOn 与 CatV2TON 的 README 标明 CC BY-NC-SA 4.0。它们可用于研究，不能直接视为本商用工作台可部署的权重。FaceFusion 的仓库与不同推理权重也要分别核对许可。本次没有下载大型模型、部署 GPU 推理服务或宣称接入以上专用引擎。

当前执行复用平台已配置、明确支持视频与图片参考的模型任务渠道。上述项目指导输入拆分、操作范围、时序要求和验收点；通用生成模型对人脸、遮挡、文字及服装细节的保持能力，需要实际成片确认。模型任务完成只代表返回了视频，不代表专业换装质量通过。

## 保存、恢复与声音交付

作品采用 `kind: "fashion-video"`，共用 `/ecommerce/product-videos` 的私有记录与 CAS revision。它与图片 `fashion`、普通商品视频及复刻作品列表隔离，不新增数据表。后端强校验工具所需素材、单元与图片配对、资源归属/类型、任务状态和输出记录。原片、切段、生成与合成输出必须是已就绪视频，人物、衣物和身份引用必须是图片。

切段的幂等键先保存，再提交切段任务；视频单元使用固定操作编号。取得任务 ID 后立即保存，恢复沿用原任务，不以刷新为理由重新收费。失败任务保留原错误与资源；用户明确生成新版本才创建新的单元。关闭窗口或“停止等待”只停止前端监听，后台任务保留。

最终交付按实际生成视频的时长和尺寸合成。生成短于目标片段时拒绝假装完整交付。声音有三种方式：

- 静音：最终生成画面轨静音。
- 模型声音：所选模型必须明确支持声音生成，保留其输出声音。
- 原片声音：生成画面轨静音，将已经切好的原视频音轨从零点对齐，避免把原片未选部分混进成片。切段没有确认音轨时，包括恢复路径，都不提交新的模型任务。

时间线渲染接口没有提交幂等键，因此先保存“已开始提交”，再调用渲染。提交结果未知时不自动再发一次；可从任务中心核对并关联包含当前生成资源的原渲染任务。最终资源返回后才记为“已交付”，此前预览明确标为模型原始视频。

## 验证边界

专项测试覆盖源视频与图片真实任务 payload、精确切段、首帧展示、批量配对、历史恢复、未知渲染不重提、原声与短视频拒绝、账号切换以及后端保存/重读、CAS、跨账号和资源类型校验。真实浏览器验收使用生产首页、弹窗、上传与生成服务，合成素材和外部任务响应用于隔离费用与用户数据；不能把这类测试写成上游模型成片已通过。

隔离的真实服务已完成资源上传、5秒精确切段、静音和原声两种时间线渲染；ffprobe确认5.000秒，PCM检查确认静音与测试原声。Wan视频参考实测卡在本地存储没有配置公网素材访问地址，尚未拿到上游成片。URL型协议不能随意改成Base64；实际使用需先配置可供模型读取的公网素材域名或OSS。4–7秒切段使用接口最低8秒上限与精确ranges，输出仍按所选时长，不扩展原片范围。

查看开头、中段、结尾及转身遮挡后的身份、头发、衣物轮廓、印花和文字；再核对原动作顺序、手部接触、光照边缘、片段时长和声音。未确认部位应保留不确定性，不能用“成功”状态代替质量验收。
