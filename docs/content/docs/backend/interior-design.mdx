室内设计页位于 `/interior`，把房间照片、毛坯照片、线稿或白模截图生成装修效果图。页面受「功能开放 → 室内设计」（`interiorEnabled`）控制，默认关闭。生成沿用宿主的模型报价、任务队列、计费、取消和资源存储，不另起生成链路。

## 两种交互模式

- **快速出图**：面向业主。展示出图方式、图片、空间、风格、补充要求、张数和图像模型；专业参数按默认值。
- **专业模式**：面向设计师和装企。额外开放画面比例、画质和标记为 `proOnly` 的参数。

后台「设置」决定默认模式和是否允许用户切换。每种出图方式有面向对象（`quick` / `pro` / `both`），服务端按它校验，前台隐藏不作为权限依据。

## 模型选择

出图方式可以配「默认模型」和「快速 / 专业可选模型」；全局设置还有一个「全局默认模型」。出图方式的默认模型优先于全局默认模型，下面统称“默认模型”。可选范围为空表示不限制，默认模型总在可选范围内。

- 两种模式均为：用户选择（不在可选范围内时报错）> 推荐默认模型 > 可选范围里的第一个。

页面切换出图方式、切换交互模式、「再来一次」时按同样的顺序预选模型，两种模式均保留用户已选且在范围内的模型。提交与报价传递同一个模型引用，非法选择不能静默换成收费默认模型。服务端只接受系统渠道模型或前台逻辑模型。

## 内置出图方式

| 标识                 | 名称          | 面向 | 输入                | 说明                                                     |
| -------------------- | ------------- | ---- | ------------------- | -------------------------------------------------------- |
| `style-redesign`     | 风格改造      | 两者 | 房间照片            | 参数「改造强度」：只换软装 / 软装+硬装 / 全部重做        |
| `rough-to-finished`  | 毛坯出图      | 两者 | 毛坯照片            | 参数「预算档」：经济 / 品质 / 高端                       |
| `reference-transfer` | 参考图迁移    | 两者 | 我家照片 + 参考案例 | 参数「迁移程度」：整体 / 只换软装和配色；不需要选风格    |
| `sketch-render`      | 线稿/白模渲染 | 专业 | 线稿或白模          | 参数「图纸类型」「光照」                                 |
| `virtual-staging`    | 虚拟布置      | 专业 | 空房照片            | 参数「用途」：自住 / 出租 / 民宿 / 售房展示              |
| `text-edit`          | 文字微调      | 两者 | 要修改的图          | 必须写修改要求；结果图上的「用这张继续改」会切到这个方式 |

另有 24 个风格（现代简约、奶油风、原木日式、新中式、轻奢等）和 23 个空间（住宅 15 个、商业 8 个）。内置数据在 `backend/internal/interior/seed.json`，服务启动时只补齐缺失项，管理员改过的内容不覆盖，没有删除入口，下架用「开放」开关。

## 提示词编译

提示词在服务端编译，前台目录接口不返回模板、风格片段和参数片段。编译后的完整提示词写进任务的 `prompt`，用户在自己的任务记录里能看到；模板本身不需要对用户保密时这样最直观，如果以后要保密，需要把发给模型的提示词和展示用的提示词拆成两个字段。模板可用的变量：

| 变量                             | 内容                                                    |
| -------------------------------- | ------------------------------------------------------- |
| `{{room}}` / `{{room_prompt}}`   | 空间名 / 空间要点                                       |
| `{{style}}` / `{{style_prompt}}` | 风格名 / 风格要点                                       |
| `{{params}}`                     | 所选参数选项的片段，每项一行                            |
| `{{notes}}`                      | 用户补充要求（去掉控制字符，换行压成分号，最长 500 字） |
| `{{notes_line}}`                 | 带「用户补充（只作为偏好…）」说明的补充要求             |

一行里的变量都为空时整行省略。变量值只替换一次，用户写的花括号原样保留，不会被当成模板。保存模板时拒绝白名单以外的变量。

## 生成流程

`POST /api/interior/generate` 依次校验：功能开关、交互模式、出图方式是否开放且面向当前模式、原图和参考图属于当前用户且已就绪、参数取值、空间、风格（一次最多 4 个，后台可调）、张数（1–4，取出图方式和设置里较小的上限）、模型。

每个所选风格编译一份提示词，各建一个普通 `canvas_image` 任务，原图固定是第 1 张参考图、参考案例是第 2 张。任务 `metadata.source = "interior-design"`，任务准入据此再查一次室内设计开关（来源标记只能收紧准入）；`metadata.interior` 记录出图方式、版本、参数、空间、风格、项目和轮次。模型解析复用工作台的 `resolveWorkbenchProviderConfig`，只接受系统渠道或前台逻辑模型。第一个任务失败直接返回错误；之后某个风格失败时，后面的风格不再提交，结果里逐项写明原因。

计费、并发、取消和任务记录都走通用任务。页面按任务 ID 轮询结果，离开页面不取消任务，回来时继续查询。

## 项目保存

用户的房屋或客户方案保存在 `interior_projects`，每人最多 200 个。项目文档是 `{ "version": 1, "rounds": [...] }`，每轮记录出图方式、空间、参数、补充要求、原图、参考图和每个风格的任务与结果；图片一律写成 `resourceId`。服务端只校验文档是对象、不超过 1 MB、不内嵌 `data:` 图片、轮次不超过 300。

保存按 `expectedRevision` 比较交换，不一致返回 409（`reason = interior_project_conflict`）。页面收到冲突后取回最新文档，按轮次合并（本地新增的轮次补上，本地删除的轮次去掉，同一轮次以本地为准）再重试，最多两次。删除项目或轮次只删除记录，图片保留在资产里。

切换或新建项目前，页面先把当前项目存好；保存失败时不切换，弹窗提示先重试保存，避免已扣费的出图记录丢失。项目已在别的窗口删掉这类存不上的情况，用户可以确认放弃这些记录再切换或新建，删除时遇到 404 也照常从本地移除。出图请求进行中不能切换、新建或删除项目。

资源引用快照读取项目文档和出图方式、风格、空间的封面，素材删除和孤儿清理不会清掉仍被项目引用的图片。待检查的资源不超过 100 个时，先按资源 ID 文本预筛项目，只解析可能引用它们的文档。

## 接口

前台接口都要求登录并打开室内设计开关；写接口按 `CanvasWritePerMinute` 限流，出图按 `TaskCreatePerMinute` 限流，一次请求按所选风格数计次（每个风格一个任务）；风格数本身超过这个上限时直接返回 429 说明原因，不消耗计数。请求体严格解析（未知字段报错），上限约 1 MB。

| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/interior/catalog`                            | 开放的出图方式、风格、空间和前台设置；不含任何提示词                                                                                                                                                                |
| `POST /api/interior/generate`                          | 出图，返回实际使用的模型、张数、参数和每个风格的任务回执或错误                                                                                                                                                      |

| `GET /api/interior/projects`                           | 项目列表（不含文档）                                                                                                                                                                                                |
| `POST /api/interior/projects`                          | 新建项目 `{ name, kind, document? }`，`kind` 为 `home` 或 `client`                                                                                                                                                  |

全局设置存在 `system_settings` 的 `interior_settings` 键：`defaultSurface`、`allowSurfaceSwitch`、`defaultModel`、`maxStylesPerRun`（1–4）、`maxCountPerStyle`（1–4）。没有保存过时用默认值；保存过但无法解析时报错，不静默回退。

## 后台页面

后台「室内设计 → 室内设计管理」（`/admin/interior`，默认进概览）分七个标签：

- **概览**（`/admin/interior/overview`）：近 30 天出图次数、成功率、出过图的人、项目数，没设默认模型时提醒去设置，近 14 天趋势，各出图方式、热门风格、空间和用到的模型，最近失败（点开直接看那条记录）。
- **出图记录**（`/admin/interior/records`）：所有用户的每一次出图，按出图方式、状态和用户筛选；详情抽屉（`?record=`）里是原图、效果图、参考图、出图设置、参数和完整提示词。室内设计任务按任务输入里的 `metadata.source=interior-design` 识别，任务表没有单独的来源列。

- **出图方式**（`/admin/interior/modes`）：名称、面向、输入（原图、可选参考图）、是否必选空间和风格、是否必须写修改要求、每风格最多张数、默认模型、专业模式可选模型、提示词模板和参数（JSON）。
- **风格**（`/admin/interior/styles`）与 **空间**（`/admin/interior/rooms`）：名称、分组、简介、提示词片段、标签、排序和开放状态。
- **知识库**（`/admin/interior/knowledge`）：AI 方案分析和 3D 建模参考的知识，按类别、状态（启用、停用、改过的内置、后台新增）和关键词筛选；可以新增、编辑、停用，后台新增的可以删除，改过的内置条目可以恢复原内容。保存后下一次分析和建模就按新内容取。
- **设置**（`/admin/interior/settings`）：默认交互模式、是否允许切换、全局默认模型、一次对比几个风格、每个风格最多几张。

出图价格按所选模型在「渠道与模型」里的单价计算，对外开放前要先配好模型价格。

## 页面上的辅助操作

- **出图记录**：每一轮是一组画廊，原图排第一张，后面每张效果图一张卡片，都按原图比例显示；轮次标题旁是状态和时间，下面一行是空间、风格、张数、比例和模型，再下面是补充要求。生成中的卡片显示已等待的时间，失败的卡片显示原因和「用这组设置重试」，查询停住的可以「重新查询」。下载、继续改、生成 3D 模型在鼠标移到卡片上时出现，触屏上一直显示。
- **拖动对比**：大图默认把原图叠在效果图上，左右拖动分隔线对比；也能切到只看效果图或原图。分隔线可以用键盘左右键移动。
- **再来一次**：每一轮的「用这一轮的设置再来一次」把出图方式、空间、风格、参数、补充要求、张数、比例和原图回填到左侧，并尽量切回这一轮当时的交互模式；确认后再点生成，不会自动扣费。已下架的风格、空间和参数选项会被跳过。失败的风格有「用这组设置重试」，只回填这一个风格。
- **下载本轮**：一轮里所有生成成功的图逐张交给浏览器下载，每张间隔 0.4 秒。
- **粘贴上传**：在页面上按 Ctrl+V 粘贴图片。没有原图时填原图；已有原图且出图方式要参考图时填参考图。在输入框里粘贴带文字的内容（例如从 Office 复制）和在弹窗里粘贴都不会被当成图片。
- **封面**：后台可以给出图方式、风格和空间上传封面。出图方式的封面显示在前台卡片上，风格的封面显示在风格按钮上。上传过程中编辑弹窗不能关闭，避免封面写到下一条记录上。

## 3D 模型

页面上的「3D 模型」生成走通用文本任务（`POST /api/tasks`，`mode=text`，`metadata.source=interior-design`，所以同样受「室内设计」开关控制、按所选文本模型计费），只多读一个知识库接口：

0. 取知识：范围默认「AI 判断」，只传一张图或写一句话也能生成。先按用户选的范围、空间、风格和描述取知识（`GET /api/interior/knowledge`），记进 `knowledge[]`。
1. 读图出方案（一次文本任务，`stage=spec`，`streamText` 打开）：`web/src/lib/interior/scene-spec.ts` 的 `buildSceneSpecPrompt` 让模型按固定顺序写一份 JSON：先写 `reading`（3–8 条读图或设计记录：总尺寸、空间位置、门窗朝向、柱子楼梯、家具思路），再写 `scope`（AI 判断时）、`roomKey`、`styleKey`、`renderNotes`，然后是 `grid`（轴网：照图纸尺寸标注累加出的每条墙中线 `x[]`、`z[]`，总开间 `width`、总进深 `depth`，外墙轴线框在附图里的千分比位置 `image`）、配色、楼层（层高、房间矩形、L 形房间写多个同名矩形或 `rects`、相通不砌墙的 `open`、门、窗、柱子 `pillars`、楼梯、阳台、家具）、屋顶和庭院。有附图时提示词给出读图步骤：图纸上方是北、右方是东，原点在左上角轴线交点，先读最外道总尺寸再读分段尺寸，房间边界只用轴网上的数，门窗写中心坐标 `at`、宽度、开向 `into` 和门轴 `hinge`，飘窗写 `bay`，图上画了家具的写 `pos` 和 `facing`，最后自检外轮廓和总尺寸。以前先做一轮方案分析（`stage=analyze`）再出方案，要看两次图；旧记录里停在这一步的照旧续跑。
2. 收紧方案（`normalizeSceneSpec`）：照图纸把毫米数直接抄进来时（房间坐标跨度超过 150）整份换算成米；坐标对齐到 5 厘米、在 ±60 米内；所有楼层的房间和阳台边界相差不到 20 厘米的归成同一条墙中线（有轴网用轴网上的值），楼梯和柱子不参与对齐；同名又挨着的矩形连成一个房间（拆出来的叫「客厅#2」，记 `part`，之间不砌墙）；最多 5 层、30 个房间、40 扇门、60 组窗、80 件家具（42 种类型）、40 根柱子；不认识的类型丢掉，没有房间时报错。写了轴网总尺寸、房间拼出来又差得多时（超过 0.3 米或 3%），`specDimensionCheck` 在记录上留一句提醒。
3. 生成几何（`scene-compile.ts` 的 `compileSceneSpec`，纯函数）：按房间边界自动解出墙，外墙 0.24 米、内墙 0.12 米；相邻墙按固定规则一面延长一面缩短，墙与墙不会叠在同一平面上（`web/test/interior-scene-spec.test.ts` 有共面重叠检查）。门窗按 `at` 落在墙上（没写就居中或均匀排开，和已有洞口挤在一起时就近挪开），平开门按开向转开 78 度、门轴在 `hinge` 一头，另有双开门、推拉门、垭口、入户门，飘窗带窗台板、坐垫和两侧玻璃；没写门的房间自动开门。柱子按方案砌到顶，和墙重叠的部分去掉。房间里自动补踢脚线（门洞和落地窗处断开），客厅、卧室、书房的外窗挂窗帘，沙发背后和床头上方挂画。上层楼板盖住下层轮廓，退台的地方变成露台并加玻璃栏杆；楼梯处挖洞。家具写了 `pos` 的按位置摆（离墙不到 0.4 米的贴墙）；没写位置的按墙的情况摆：沙发和电视墙选一对相对且都够长的墙，床头靠不开窗的实墙，衣柜靠床旁边的墙，书桌靠窗，卫生间的淋浴和马桶靠门对面；茶几、地毯、单椅、落地灯跟着沙发；高柜不挡窗，家具互相不重叠。家具由 `scene-furniture.ts` 按真实尺寸拼成，灯罩、花盆、洁具用旋转体，桌面、浴缸、窗帘、汽车用挤出体。另外给出房间标注（名称、开间 × 进深、面积）和外围两道尺寸线（轴线分段和总尺寸，单位毫米）。户型和单个房间的外墙带 `facade` 标记和一截 0.12 米的矮墙。
4. 边写边搭：任务按流式返回（`GET /api/tasks/:id/text-events`），`use-interior-scene-tasks.ts` 每 300ms 把收到的文字交给页面；事件流不可用时退回轮询，轮询结果里的 `textDraft` 照样往外送。`scene-stream.ts` 的 `readPartialScene` 把半截 JSON 退回到最后一个写完的元素、用 `jsonrepair` 补齐括号，再按同样的规则收紧，没写完的房间和家具不会出现。生成中的页面（`interior-scene-build.tsx`）左边是正在长大的模型：先按轴网画尺寸线，房间、墙、门窗、家具写出来一样搭一样，新的部分从地面升起来，镜头慢慢转、取景跟着模型变大；右边是步骤（读图、轴网和尺寸、房间、门窗、家具、屋顶和庭院）、已用时间、已写字数、AI 读图记录和用户的附图。系统要求减少动效时不转镜头、不做升起动画。
5. 保存：生成好的场景（`version: 2`，含方案 `spec` 和统计 `stats`）存成 JSON 文件资源（`kind=file`），项目文档 `scenes[]` 里只记进度和 `sceneFile.resourceId`，资源引用扫描据此保留这些文件。方案里的读图记录、`renderNotes`、AI 判断的范围、空间和风格写回这条记录（`brief`、`scope`、`roomKey`、`styleKey`）。
6. 局部调整：已完成模型下方选择真实房间或单件家具，也可以点击三维房间标注选择房间。对话只发送选定目标数据和修改要求，返回最小 JSON 修改对象；`scene-local-edit.ts` 校验目标身份、字段、家具类型、颜色、坐标和尺寸，再写入原场景的副本。房间可调整地面材料和本房间家具；单家具可调整类型、颜色、位置、宽深和朝向，房间边界、墙体、轴网及其他房间的数据保留。选择「整套方案（可调整结构）」才沿用完整方案修改。
7. 手动调整：房间提供地面材料，家具提供类型、颜色、位置、宽深和旋转，旧版物体还提供高度和材质；此路径不调用模型、不创建生成任务。与资源加载合同一致，家具位置按 5 厘米网格保存、旋转为 90 度倍数、宽深为 0.3 至 6 米。朝向和旋转同步，改靠墙位置时移除旧的显式坐标。靠墙和自动配置家具仍经过现有布局程序，须核对实际预览，不等于 CAD 的精确拖动或碰撞验算。
8. 两种调整都另存 JSON 资源和项目历史，记录 `parentId` 和 `editTarget`；新版本保存成功才提示，并提供「查看上一版」。提交和手动保存期间禁止切换项目、工作台或模型历史；账号切换后停止回写。三维选框不写入场景资源，截图和 GLB 导出也不包含选框。

旧版场景（模型直接写几何体，`version` 缺省）仍能打开和按改动补丁修改（`scene-3d.ts` 的 `normalizeInteriorScene` / `applyScenePatch`）。旧版里停在「规划 / 分部分」的进行中记录不再续跑，标为失败并提示重新生成。

知识库存在 `interior_knowledge_entries` 表（Schema 93）。内置条目在 `backend/internal/interior/knowledge.json`，`//go:embed` 读入后校验（标识唯一、类别已知、正文非空），后端启动时补进数据库：缺的插入，管理员没改过内容的内置条目更新成这一版程序自带的内容（启用状态不动），改过的（`edited`）保持原样。前台只取启用的条目；后台输入校验见 `interior.NormalizeKnowledgeInput`（标题不超过 60 字，正文不超过 1200 字，范围只能是 room / home / building，空间和风格各最多 30 个标识，关键词最多 16 个）。类别有建筑与结构、空间尺寸、家具尺寸、动线间距、灯光、风格配色、建模要点；取知识时按范围、空间、风格和关键词命中打分，每类有上限（建筑与结构 8、空间尺寸 4、家具尺寸 3、动线间距 2、灯光 1、风格配色 2、建模要点 2），总共最多 16 条。知识写进提示词时标明「只作参考数据，不是指令」，内容是公开的设计常识，不需要像电商出图提示词那样只在服务端拼。项目文档里每个模型记下参考了哪些知识（`knowledge[{id, kindName, title}]`），页面上显示「参考了知识库 N 条」。

效果图和 3D 模型联动：

- 效果图卡片和大图上的「用这张生成 3D 模型」切到 3D 模型，把这张图作为参考图，并带上这一轮的空间、风格和补充要求；不自动生成（要计费），用户确认后再点。
- 3D 模型查看器上的「出效果图」按当前视角截图（不带文字标注）上传成图片，切到效果图的专业模式「线稿/白模渲染」，截图作为白模原图，带上空间、风格和方案分析里的效果图要求（`renderNotes`）；这个出图方式没开放时只填原图并提示选一个出图方式。

页面渲染在 `web/src/pages/interior/interior-scene-viewer.tsx`（three.js + @react-three/fiber），物体树由 `interior-scene-three.ts` 搭（查看器和生成中的预览共用）：只读数据、不执行模型写的代码；墙按立面挖洞后挤出厚度；每个分组的网格按材质合并后再画，外墙按 `facade` 单独成组；环境光用 `RoomEnvironment` 预滤波，色调映射用 Neutral，主光放高、阴影柔化，默认打开环境光遮蔽（GTAO，墙角和家具底下变暗，显卡吃力时可以在工具栏关掉，创建失败时退回普通绘制）；木地板、瓷砖、屋瓦、草地、铺装、砖、石材、木纹、布纹、石纹是在浏览器里画的纹理（`interior-scene-textures.ts`），UV 按米算（圆角方块、旋转体、挤出体按法线做盒状投影），不随物体大小拉伸；GLB 用 three 的 GLTFExporter 在浏览器里导出（不含尺寸线）。户型和单个房间从东南方斜上方约 57 度取景，朝向镜头的外墙整面隐藏（连同门窗、窗帘、踢脚线、挂画，以及靠在这面墙上的电视、背景墙、吊柜、烟机和镜子这些挂墙零件），换成矮墙，转到哪面剖哪面，俯视时不剖，工具栏可以关掉；生成中的预览同样剖开。「尺寸」显示外围尺寸线和每个房间的开间 × 进深、面积（户型和房间默认打开）。有附图时「对照附图」先在角上并排显示附图，方案读出了 `grid.image` 时再点一次把附图半透明叠在俯视图上，图纸和模型哪里没对上一眼能看出来。「剖切」选一层后隐藏更高的楼层和屋顶，这一层的墙只画到 1.2 米；只有一层的户型也能剖切，转到任何角度都能看清每个房间。旧版场景保留防闪烁处理（每个物体按序号放大不超过约 0.5%、对数深度缓冲）；新版几何本身没有共面重叠，不需要。文字标注被不透明的墙、楼板、屋顶挡住时隐藏（玻璃和隐藏的分组不算遮挡），视角变化时每 120ms 最多检查一次。
