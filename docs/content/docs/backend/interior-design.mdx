室内设计页位于 `/interior`，把房间照片、毛坯照片、线稿或白模截图生成装修效果图。页面受「功能开放 → 室内设计」（`interiorEnabled`）控制，默认关闭。生成沿用宿主的模型报价、任务队列、计费、取消和资源存储，不另起生成链路。

## 两种交互模式

- **快速出图**：面向业主。只展示出图方式、图片、空间、风格、补充要求和张数；模型固定用管理员配置的默认模型，专业参数按默认值。
- **专业模式**：面向设计师和装企。额外开放出图模型、画面比例、画质和标记为 `proOnly` 的参数。

后台「设置」决定默认模式和是否允许用户切换。每种出图方式有面向对象（`quick` / `pro` / `both`），服务端按它校验，前台隐藏不作为权限依据。

## 内置出图方式

| 标识 | 名称 | 面向 | 输入 | 说明 |
| --- | --- | --- | --- | --- |
| `style-redesign` | 风格改造 | 两者 | 房间照片 | 参数「改造强度」：只换软装 / 软装+硬装 / 全部重做 |
| `rough-to-finished` | 毛坯出图 | 两者 | 毛坯照片 | 参数「预算档」：经济 / 品质 / 高端 |
| `reference-transfer` | 参考图迁移 | 两者 | 我家照片 + 参考案例 | 参数「迁移程度」：整体 / 只换软装和配色；不需要选风格 |
| `sketch-render` | 线稿/白模渲染 | 专业 | 线稿或白模 | 参数「图纸类型」「光照」 |
| `virtual-staging` | 虚拟布置 | 专业 | 空房照片 | 参数「用途」：自住 / 出租 / 民宿 / 售房展示 |
| `text-edit` | 文字微调 | 两者 | 要修改的图 | 必须写修改要求；结果图上的「用这张继续改」会切到这个方式 |

另有 24 个风格（现代简约、奶油风、原木日式、新中式、轻奢等）和 23 个空间（住宅 15 个、商业 8 个）。内置数据在 `backend/internal/interior/seed.json`，服务启动时只补齐缺失项，管理员改过的内容不覆盖，没有删除入口，下架用「开放」开关。

## 提示词编译

提示词只在服务端编译，前台目录接口不返回模板、风格片段和参数片段。模板可用的变量：

| 变量 | 内容 |
| --- | --- |
| `{{room}}` / `{{room_prompt}}` | 空间名 / 空间要点 |
| `{{style}}` / `{{style_prompt}}` | 风格名 / 风格要点 |
| `{{params}}` | 所选参数选项的片段，每项一行 |
| `{{notes}}` | 用户补充要求（去掉控制字符，换行压成分号，最长 500 字） |
| `{{notes_line}}` | 带「用户补充（只作为偏好…）」说明的补充要求 |

一行里的变量都为空时整行省略。变量值只替换一次，用户写的花括号原样保留，不会被当成模板。保存模板时拒绝白名单以外的变量。

## 生成流程

`POST /api/interior/generate` 依次校验：功能开关、交互模式、出图方式是否开放且面向当前模式、原图和参考图属于当前用户且已就绪、参数取值、空间、风格（一次最多 4 个，后台可调）、张数（1–4，取出图方式和设置里较小的上限）、模型。

每个所选风格编译一份提示词，各建一个普通 `canvas_image` 任务，原图固定是第 1 张参考图、参考案例是第 2 张。任务 `metadata.source = "interior-design"`，任务准入据此再查一次室内设计开关（来源标记只能收紧准入）；`metadata.interior` 记录出图方式、版本、参数、空间、风格、项目和轮次。模型解析复用工作台的 `resolveWorkbenchProviderConfig`，只接受系统渠道或前台逻辑模型。第一个任务失败直接返回错误；之后某个风格失败时，后面的风格不再提交，结果里逐项写明原因。

计费、并发、取消和任务记录都走通用任务。页面按任务 ID 轮询结果，离开页面不取消任务，回来时继续查询。

## 项目保存

用户的房屋或客户方案保存在 `interior_projects`，每人最多 200 个。项目文档是 `{ "version": 1, "rounds": [...] }`，每轮记录出图方式、空间、参数、补充要求、原图、参考图和每个风格的任务与结果；图片一律写成 `resourceId`。服务端只校验文档是对象、不超过 1 MB、不内嵌 `data:` 图片、轮次不超过 300。

保存按 `expectedRevision` 比较交换，不一致返回 409（`reason = interior_project_conflict`）。页面收到冲突后取回最新文档，按轮次合并（本地新增的轮次补上，本地删除的轮次去掉，同一轮次以本地为准）再重试，最多两次。删除项目或轮次只删除记录，图片保留在资产里。

资源引用快照读取项目文档和出图方式、风格、空间的封面，素材删除和孤儿清理不会清掉仍被项目引用的图片。

## 接口

前台接口都要求登录并打开室内设计开关；写接口按 `CanvasWritePerMinute` 限流，出图按 `TaskCreatePerMinute` 限流。请求体严格解析（未知字段报错），上限约 1 MB。

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/interior/catalog` | 开放的出图方式、风格、空间和前台设置；不含任何提示词 |
| `POST /api/interior/generate` | 出图，返回实际使用的模型、张数、参数和每个风格的任务回执或错误 |
| `GET /api/interior/projects` | 项目列表（不含文档） |
| `POST /api/interior/projects` | 新建项目 `{ name, kind, document? }`，`kind` 为 `home` 或 `client` |
| `GET /api/interior/projects/:projectId` | 读取项目和文档 |
| `PUT /api/interior/projects/:projectId` | 整体保存 `{ name, kind, document, expectedRevision }` |
| `DELETE /api/interior/projects/:projectId` | 删除项目 |

后台接口只校验管理员，不受功能开关限制，方便开放前先配置。修改带 `version` 比较交换，冲突返回 409（`reason = interior_version_conflict`），每次修改写管理审计。

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/admin/interior/modes` | 全部出图方式，含模板和参数片段 |
| `POST /api/admin/interior/modes` | 新增出图方式 |
| `PUT /api/admin/interior/modes/:id` | 修改出图方式（标识不能改） |
| `GET /api/admin/interior/presets?type=style\|room` | 风格或空间列表 |
| `POST /api/admin/interior/presets` | 新增风格或空间 |
| `PUT /api/admin/interior/presets/:id` | 修改风格或空间（类型和标识不能改） |
| `GET /api/admin/interior/settings` | 全局设置 |
| `PUT /api/admin/interior/settings` | 保存全局设置 |

全局设置存在 `system_settings` 的 `interior_settings` 键：`defaultSurface`、`allowSurfaceSwitch`、`defaultModel`、`maxStylesPerRun`（1–4）、`maxCountPerStyle`（1–4）。没有保存过时用默认值；保存过但无法解析时报错，不静默回退。

## 后台页面

后台「室内设计 → 室内设计配置」（`/admin/interior`）分四个标签：

- **出图方式**（`/admin/interior/modes`）：名称、面向、输入（原图、可选参考图）、是否必选空间和风格、是否必须写修改要求、每风格最多张数、默认模型、专业模式可选模型、提示词模板和参数（JSON）。
- **风格**（`/admin/interior/styles`）与 **空间**（`/admin/interior/rooms`）：名称、分组、简介、提示词片段、标签、排序和开放状态。
- **设置**（`/admin/interior/settings`）：默认交互模式、是否允许切换、全局默认模型、一次对比几个风格、每个风格最多几张。

出图价格按所选模型在「渠道与模型」里的单价计算，对外开放前要先配好模型价格。

## 当前边界

- 局部替换只有「文字微调」，还没有框选或蒙版重绘。
- 出图方式和风格的封面图字段已预留，后台还没有上传入口。
- 没有室内设计专用的 Agent、材质库和灵感墙。
