## 视频请求日志生成内容

- 后台详情：`web/src/pages/admin/components/api-log-detail-drawer.tsx` 挂载 `api-log-generation-content.tsx`，提示词编号解析在 `pages/admin/logs/generation-content.ts`。原始图片可放大，视频和音频按需播放；只请求管理员日志媒体接口，不以当前账号的素材库替换原请求。
- 请求快照：`backend/internal/app/api_log_generation_content.go` 在媒体转换前保存提示词与原资源身份，详情检查来源和归属；`model/api_log_generation.go` 定义只读返回合同。请求根日志保留快照，轮询合并不覆盖。
- 资源保留：`repository/api_log_generation.go` 将日志引用纳入删除和孤儿清理；日志移除后自然释放该引用。接口在 `handler/admin_api_log_routes.go`，迁移在 `database/migrations.go`。

## 媒体资源与按需加载

- 远程 Blob：`web/src/services/resource-blob-cache.ts` 分开管理有界闲置缓存、持久化队列与活动 URL 租约；`hooks/use-cached-resource-url.ts` 对接画布图片/大图预览，`services/canvas-video-preview.ts` 在抽帧结束释放。上传预热由 `pages/canvas/use-canvas-upload.ts` 短暂借用。
- 本地降级媒体：`services/local-media-object-urls.ts` 记录同 key 的当前/旧版本 URL，供 `file-storage.ts`、`image-storage.ts` 在明确删除/会话退出时统一回收；原件继续保存在 IndexedDB。
- 媒体 Worker：`lib/canvas/canvas-video-merge.ts` 的 `runFFmpegTask` 为转码/合并/裁段/抽音轨统一串行作用域及空闲释放；`canvas-face-detection.ts` 管理识脸请求、取消、错误和空闲 Worker 回收。
- 官方插件校验：`backend/internal/app/protocol_plugins.go` 缓存每路径最新清单/摘要，不持有原包字节；落盘硬链接或流式复制核验，专项 `official_plugin_package_cache_test.go`。
- 工作区路由：`web/src/lib/workspace-route-modules.ts` 保留导航意图预取，登录不再无条件预热全部一级页面。录音测试页面仅在 `router.tsx` 的 DEV 路由注册。

## 前端主题包

主题登记与切换在 `web/src/themes/`：`registry.ts` 按皮肤 ID 查找，`load.ts` 自动载入，`apply.ts` 处理画布预设还原与品牌变量。各主题目录封装助手形象、空状态、404、字体和样式，静态资源在 `web/public/themes/`。入口通过 `application.tsx` 加载；后台外观提交在 `stores/use-appearance-store.ts` 应用当前主题。使用与扩展说明见 `web/src/themes/README.md`。

龙影水墨和云鹤仙观的皮肤参数由前端主题包与 `backend/internal/app/appearance_skins.go` 共用 `appearance_theme_packs.json`。读取旧版外观配置时，`appearance.go` 按皮肤库剩余容量补入缺少的主题，直到管理员保存新版配置。

## 电商生图台

- 成品设计检查：`lib/ecommerce-studio/design-check.ts` 定义真实成品检查提示与严格结果解析；`design-check-session.ts` 在同一标签页按用户 scope 保存操作编号和任务编号，刷新后继续原任务。`pages/ecommerce-studio/studio-design-check.tsx` 复用统一文本任务与兼容性校验，检查模型独立于全局默认。`studio-viewer.tsx` 展示检查入口，`studio-shot-tuner.tsx` 接收修正要求；`prompt-compiler.ts` 为单张修正保留商品真值并附上当前成品，编译时检查参考图名额及成品来源，`use-studio-runner.ts` 把 `revisionResourceId` 写入尝试记录，恢复提交仍编辑同一候选。文字修改由图片模型一起完成。
- 图文区域参考：`pages/ecommerce-studio/studio-layout-guide.ts` 仅在生成前准备无文案的区域草图，在参考名额有余时追加，不挤掉商品或卖家参考，不参与成品合成；它属于模型提示，不能保证模型遵守。单张修正以已有成品为编辑起点，不再附区域草图。OpenAI Images 官方插件与旧手写多图路径统一使用 `image[]`，单图仍用 `image`，请求测试核对实际字节及顺序。
- 窗沿角色：`components/canvas/agent-window-dock.tsx` 作为输入区的绝对定位锚点，将角色固定在输入上沿并向内留12px，不占消息或输入高度。`agent-skin-scene.css` 收起时保留48px，媒体按透明头顶偏移；`agent-avatar-video.tsx` 测量绿幕实际顶边，`agent-window-perch.tsx` 计入视频contain留白，暂停仍显示首帧。工作与互动自动展开，交互和自动收回仍由perch管理。

- 页面 `web/src/pages/ecommerce-studio/`：`index.tsx` 生图表单与生成记录两栏；`studio-form.tsx` 表单与识别填写；`studio-results.tsx`、`studio-viewer.tsx` 生成记录与大图查看，`studio-viewer-stage.tsx` 是大图的缩放与拖动；`studio-header.tsx` 商品切换、新建、删除与保存状态；`studio-uploads.tsx`、`studio-upload.ts` 商品图与参考图上传；`studio-delivery.ts` 长图、切片与打包；`use-studio-store.ts` 去抖保存与冲突重套；`use-studio-runner.ts` 识别、出图策划（`plan`，按当前出图类型的范围）、按镜头出图、并发与回到页面后的任务续接；`use-studio-agent.ts` 把当前商品交给全局助手；`studio-suite-picker.tsx` 选套图模板（后台精选与内置模板库，列表与预览复用 `components/canvas/ecommerce-template-catalog.tsx`）；`studio-shot-list.tsx` 套图镜头清单的勾选与排序，策划过的屏在这里展开修改；`studio-shot-tuner.tsx` 大图里的单张调整与提示词预览；`studio-dossier.tsx` 商品档案核对；`studio-model-cast.tsx` 表单里的模特设定与模特库选择弹窗。路由 `/studio` 在 `web/src/router.tsx`，受 `RequireFeature feature="ecommerceStudioEnabled"` 保护；侧栏入口在 `workspace-sidebar-nav.tsx`。

- 接口 `web/src/services/api/ecommerce-studio.ts` → `backend/internal/handler/ecommerce_studio.go`（`RegisterEcommerceStudioRoutes`，在 `api.go` 单独注册）→ `app/ecommerce_studio.go`，复用 `repository/ecommerce_library.go` 的修订号保存，资源引用扫描在 `repository/resource_reference.go`。「商品档案」与「出图策划」能力的默认指令与准入在 `app/ecommerce_defaults.go`、`app/ecommerce_settings.go`（`ecommerceStudioCapability` 让这两项不受旧画布总开关约束）；与电商 Agent 共用知识库的检索与注入在 `app/ecommerce_studio_knowledge.go`：商品档案复用 `retrieveEcommerceKnowledge` 后按类型过滤，出图策划用 `rankEcommerceKnowledge`（创作类型按 `studioPlanKind`），`app/ecommerce_studio_references.go` 再从内置套图库（`ecommerce_catalog.go` 的 `loadEcommerceCatalog`）挑同类爆款套图附在后面（`app/ecommerce_creative_context.go`，限量前的全部候选）按 `ecommerceStudioPlanKnowledgeTypes` 分类型取。功能开关 `ecommerceStudioEnabled` 定义在 `internal/platform/feature_availability.go`，任务准入在 `app/task_creation.go` 的 `requireTaskGenerationFeatures`。

## 视频复刻 · 复刻工作台与元素替换

- 后端切段：`backend/internal/app/ecommerce_product_video_split.go` 负责 `POST /api/ecommerce/product-videos/splits`。任务类型是 `product_video_split`（`model.TaskTypeProductVideoSplit`），由 `task_worker.go` 分发，超时 10 分钟。
  - 不带 `ranges` 时，镜头切点复用 `video_replication_media.go` 的 `detectVideoTeardownCuts`，可以只检测选段内的一段；`planProductVideoSegments` 尽量在切点处断开，每段不超过上限、不短于 4 秒。

## 后端调用链

AutoDL 画面规格由 `app/model_capability_screen_spec.go` 读取官方插件工作流合同（精确工作流优先，未声明的 ID 回退到 `*` 默认预设），校验所选分辨率及默认值，允许自定义标签；`task_creation.go` 在价格选择之前归一化，任务校验与 `provider_video.go` 再次使用同一规则。前端 `lib/video-screen-specs.ts` 管理插件预设、所选规格与工作流切换，`ModelCapabilityEditor` 复用到系统及自定义渠道；无开关或独立草稿。

```text
HTTP 请求 -> handler -> service（稳定导入面 / 别名）-> app（组合根）-> 业务域包 -> repository/model
                                                                     |
                                                                     -> protocol / payment / generation / outbound
```

`internal/service` 只再导出 `internal/app` 的类型、常量和包级函数，handler/cmd 仍 import `internal/service`。组合根和尚未拆出的业务实现在 `internal/app`。已抽出的域包不得 import `service` 或 `app`（防回环）。共享错误码与 ID/字符串工具在 `internal/kernel`。

登录恢复仅初始化当前账号缓存与增量同步会话，不再自动读取 `GET /api/user-data/snapshot`。画布库通过分页摘要加载，打开、导出、重命名时按 ID 读取完整画布，引用素材通过批量 ID 接口读取；旧快照接口仍保留供显式调用。实现见 `internal/canvas/user_data_page.go` 和前端 `services/user-data-sync.ts`。用户库素材写入（`UpsertUserAsset` / `ReplaceUserAssets`）在 `internal/canvas/user_asset_document.go` 校验 SPA 合同：`kind`、`coverUrl`、`tags` 字符串数组，以及按类型完整的 `data`。不完整 payload 在入库时拒绝；GET 仍返回已保存的原始 JSON。上游异构 JSON 的可选字符串仍走 `stringField`；任务 ID 等关键字段走 `firstJSONString`，数字 ID 不再被当成“缺字段”。

后端托管的文本生成通过 `GET /api/tasks/:id/text-events` 返回 `progress`、`delta` 和 `terminal` 事件。`delta` 的递增事件 ID 是断线续传游标，前端使用 `?after=<id>` 恢复；分镜任务复用该通道实时接收阶段和进度，但分镜结构和 Agent 工具参数仍在完整响应结束并校验通过后原子应用，不执行半截 JSON。

## 修改原则

- HTTP 参数与响应只在 handler 处理，业务规则进入 service。
- 页面保留流程协调；可独立理解和测试的算法进入同业务域的 `lib`。
- 新增功能时只更新本页的主要入口，不增加逐文件清单。

- `backend/internal/handler/tools.go`：登录态工具列表、详情、收藏、创建与删除。
- `internal/service` 别名 → `internal/app/tools_bridge.go`（资源归属校验）→ `internal/tools`（可见性策略、输入合同、token 展开和内置种子）→ `internal/repository/tools.go`。
