# 功能清单

## LibTV 灵感广场

首页精选灵感提供“画布灵感”和“单次创作灵感”切换。登录用户可在灵感广场搜索、按标签筛选和分页浏览 LibTV 公开作品，查看成片、制作步骤、公开提示词及图片、视频、音频预览。
可独立复用的步骤支持预填到创作页，不自动生成；含引用的模板可复制到新画布，预览转换警告并确认导入，保留节点、连接、画框和多个媒体结果。公开作品查询不需要管理员的 LibTV 凭证；原有私有项目导入设置保持独立。

## 画布多窗口实时协作

同一账号在多个窗口打开同一画布时，在画布顶部正中间以紧凑入口显示在线设备数量，展开后查看“设备1、设备2”等会话。服务端统一编号，各窗口名称和颜色一致，自己所在行标记“此窗口”。只显示远端光标的小标签和轻量拖拽轮廓；只剩一个窗口时全部隐藏并停止采集光标。高频坐标按帧直接更新独立浮层，不触发 React 重渲染。WebSocket 广播临时预览和提交后的同步通知，最终内容仍经过原有 operations 保存与并发合并；正常空闲连接改为低频状态校验，断线保留轮询。未配置 Redis 支持单后端进程，配置后支持跨实例分发；不增加跨账号编辑权限。真实浏览器与部署验收见[待测试](/docs/progress/pending-test)，协议见[画布操作同步](/docs/backend/canvas-operations-sync)。

## 用户登录日志

管理员在“用户与运营 → 用户登录日志”查看密码、邮箱/短信验证码、Linux.do 的成功/失败登录、注册自动登录和主动退出。支持用户、事件、方式、结果、IP、时间范围筛选、分页、刷新、详情和失败重试；显示账号快照、设备信息和安全原因。成功记录与会话操作原子提交，重复/伪造/过期退出不产生成功事件；刷新和自然过期不计为登录/主动退出。普通用户不可访问，不记录密码或会话凭据，不补造历史。

## 个人信息

“更换头像”弹窗集中提供上传图片和系统头像两种方式。头像上传支持固定 1:1 裁剪：拖动裁剪框、调整大小、键盘移动和重置，确认裁剪后返回弹窗预览，在弹窗内保存。系统头像提供默认人像、导演、摄影师、小猫、小兔、机器人、探索者和灵感 8 款，在同一弹窗内选择并保存；保存后全局同步，刷新保持。

“账户与设置”新增“个人信息”，展示账号名称与绑定邮箱状态。用户可预览并保存个人头像或恢复系统默认头像，顶栏、侧栏、账户卡片与创作消息同步更新。密码修改与邮箱更换分别保存；修改密码需要当前密码，邮箱更换还需要新邮箱验证码，成功后退出所有登录会话。纯 Linux.do 账号可重新授权核验身份后设置本地密码或更换邮箱。沿用现有设置页、表单、按钮反馈与主题，未增加昵称、用户名或角色编辑。

## 生图与视频工作台

普通用户可分别使用生图、视频工作台。通过工具卡片选择场景，套用预设提示词，按所选模型能力配置参数和参考素材；生成结果、运行任务及历史详情在同一页面查看。管理员在「工作台工具」维护分类、图标/封面、预设、使用说明与示例素材，并在「功能开放」分别控制两个入口。新入口默认关闭；工作台任务经过统一任务与计费服务创建。

详见[生图与视频工作台](./workbench)。

## 百炼 MiniMax 视频

`dashscope-minimax-video` 独立插件接入百炼 `MiniMax/MiniMax-H3`，支持文生视频、首帧、仅尾帧、首尾帧与图像/视频/音频多模态参考。插件校验 4–15 秒、768P/2K、7000 字符提示词及媒体角色和数量，模型能力由渠道配置。任务经统一宿主鉴权、轮询与结果持久化，恢复时查询原任务；真实文生视频创建、轮询与下载已验证，多模态及应用内完整链路仍待验收。配置见[百炼 MiniMax 视频](/docs/backend/bailian-minimax-video)。

## 可美 KM Seedream 图片

`km-kemei-seedream` 声明式插件接入 Seedream 5.0 Pro / Flash 的文生图与参考图编辑，支持 URL / Base64 响应并由宿主统一保存图片。精确模型 ID 与扩展参数见插件包内 `docs/interface.md`。

协议默认 2K 方图、单张生成、最多十张参考图，提供 1K / 1.5K / 2K 共二十四个精确尺寸预设。后台能力编辑、画布选择与服务端校验同步支持 1.5K。蒙版与通用质量开关关闭；透明输出通过插件命名空间配置，并要求单张含 alpha 的参考图。供应商错误和空结果保留失败语义。

## 卡藏 Midjourney

画布接收一次任务返回的全部图片，四张结果自动组成收起的图片堆叠，可展开、选择主图和分别使用。每张图保留独立资源及素材绑定，保存、刷新和任务重复同步不会将后续图片覆盖为第一张。已有仅显示首图的成功 Midjourney 节点在重新打开画布时从原任务恢复遗漏结果，无需再次生成。

`kacang-midjourney` 统一声明式插件提供 V6/V8 特惠、V7 特惠、稳定/高速三个生图协议。选择协议后自动填入供应商比例、默认比例、参考图上限和一次提交；禁用无合同的蒙版和通用输出参数。稳定版数值 quality 通过插件命名空间设置，不与宿主分辨率档混用。

特惠使用标准图片端点，稳定/高速使用受理和任务查询端点。结果支持顶层与 data 信封，全部单图及可选四宫格封面交给宿主立即保存；失败和空结果保留真实失败语义。完整模型和字段合同见插件包内 `docs/interface.md`。

## 沧元 Midjourney

`cangyuan-midjourney` 声明式插件分别提供 V7 与 1K/2K（供应商默认 V8.2）协议。V7 使用 `midjourney-v7`；1K/2K 使用 `midjourney-1k`、`midjourney-2k`，可在提示词显式写 `--v 8.2`。一次提交固定 `n=1`，全部结果交由宿主下载保存，参考图按供应商合同发送 HTTPS URL 字符串。

两条线路的参数、编辑端点和响应格式分别适配，不自动换模型。1K/2K 返回官网 CDN 原链，HTTP 403 会如实保留保存失败与原任务重试能力；插件不能消除供应商 CDN 的访问限制。完整字段与接口合同见插件包内 README 和 `docs/interface.md`。

创作页按整个任务一次消费返回图片，保留各图片的输出序号；一次请求返回多张时，素材与消息幂等去重不会再把后续结果当作第一张合并。

后台选择这两个协议时，“能力与参数”自动使用线路专属默认值：V7 为 4000 字符、五张参考图、不支持蒙版；V8.2 默认单张编辑源图、支持蒙版和十五种比例。两者默认自动尺寸、一次提交，关闭不支持的质量、透明背景、响应格式和输出格式选项。V8.2 在模型名未明确时暂用 1K，识别到上游 `midjourney-2k` 后改为 2K，切换档位保留管理员的参考限制、默认比例和价格。像素预设由宿主换算供页面展示，提交上游仍使用比例，实际尺寸由供应商决定。

## 自定义更新公告

「站点及外观 → 更新公告」提供开关、当前版本、多版本文字／图片／视频编辑、内容排序、整行／半行布局与即时预览。关闭展示原日志，开启展示自定义内容，保存后同步工作台和后台入口；后台系统更新保留真实构建版本。详见 [自定义更新公告](/docs/backend/update-announcements)。

## AutoDL 画面规格

AutoDL 视频模型在“能力与参数 → 画面规格”直接多选当前插件工作流声明的完整分辨率，并设置默认值；配置始终可编辑并生效。卡片沿用原有标题、副标题与字段样式，不再显示自定义开关或额外说明。AutoDL ComfyUI 视频与音频 v2.3.0 通过完整分辨率标签控制横、竖、方形，不显示未声明的独立比例控件。时长、音频与参考素材配置继续各自生效。

后台保存、用户模型目录、画布参数归一化、计费规格选择、服务端校验及插件请求使用同一套所选规格。仅允许选择插件预设，不能输入新标签；至少选一项，默认值必须属于所选列表。价格档可保留全部插件预设的价格，但不会扩大实际允许生成的分辨率范围。

## 画布媒体产出模型

图片、视频、音频在生成成功并写入节点后，会冻结当时提交的产出模型。提示词面板里的模型下拉仍是下一次要用的选用模型，改下拉不会改掉已经生成的内容。画布外观中的「媒体信息」打开后，有内容的媒体节点在左下角显示产出模型；图片右下角继续显示尺寸和体积。上传、粘贴、截取、合并、提取音频和本地加工不记录产出模型。本次改动之前的节点不回填。分享页和版本预览画布不显示这块信息。

## 画布 Agent 名称、文案与形象

「站点及外观 → 画布配置」提供独立助手名称、入口文字、面板标题和欢迎/输入文案。助手名称同步用于界面和后续对话的自我介绍；名称只是数据，不改变工具权限，历史消息保留原文。支持导入授权的 Live2D Cubism 3/4 运行时 ZIP，预览后保存启用、调整高度、切回默认动态球。加载失败保留可点击的默认入口，上传和资源访问具有管理员校验和引用保护。Cubism Core 由部署者提供，真实播放待验收；不含图片自动建模。详见 [画布 Agent 外观与 Live2D](/docs/backend/canvas-agent-appearance)。

## 素材库分类与画布媒体链路

素材库支持用户手动新增、重命名和删除分类，也可以按分类或“未分类”筛选素材，并批量移动素材。删除分类不会删除素材，分类内素材会回到“未分类”。

画布中的远程图片、视频和音频展示统一使用资源文件地址，不把浏览器 Blob Object URL 写入节点或预览状态；Blob 缓存只用于导出、抽帧、供应商输入等字节处理。画布生成的视频在进入成功态前会先完成资源 Blob 缓存，缓存失败会保留失败语义，不会显示为已成功。

### 相关实现

- `web/src/pages/assets/index.tsx`：素材库分类筛选、新建、重命名、删除和批量移动入口。
- `web/src/services/api/user-data.ts`：素材分类及素材移动 API。
- `web/src/services/file-storage.ts`、`web/src/services/image-storage.ts`：远程资源地址解析。
- `web/src/services/resource-blob-cache.ts`：按用户 scope 隔离的媒体字节缓存。
- `web/src/lib/canvas/canvas-generation-task-sync.ts`、`web/src/services/project-asset-sync.ts`：生成视频缓存完成后再写入成功结果。

## 大规模画布保存

单次变更多于 500 条 operations 时，客户端按原顺序分批提交，并在每批发出前保存可恢复的请求。全部批次确认后才完成整份画布保存；中途失败保留未确认内容和未提交操作，响应丢失则用原请求 ID 与正文重放。每批是独立事务，部分批次成功不等于整份画布已经保存。协议边界见 [HTTP API](/docs/backend/http-api)。

## 画布连线可读性与底部工作条

画布左下角自动整理节点旁提供“设置隐藏节点连线”开关。开启后默认隐藏连线；鼠标划过、聚焦或选中节点时显示该节点关联的连线，已选中的连线保持可见。设置按浏览器保存，并同时应用于视觉层和连线命中层，避免隐藏连线仍可点击。

底部工作条将素材入口改为“素材 + 数量”标签按钮；手势切换保持纯图标胶囊滑块，使用指针 / 抓手图标和单个圆形选中滑块，保留悬停提示、键盘语义和原有操作。

### 相关实现

- `web/src/lib/canvas/canvas-connection-visibility.ts`：隐藏连线筛选和本地设置。
- `web/src/pages/canvas/project.tsx`、`web/src/components/canvas/canvas-zoom-controls.tsx`：画布状态、开关和渲染接线。
- `web/src/components/canvas/canvas-asset-tray.tsx`、`web/src/lib/canvas/tool-registry/definitions/main-toolbar-tools.tsx`：底部工作条入口。

## 文本节点尺寸联动

文本节点的普通文本、富文本和编辑态输入框共用同一套字号缩放规则。节点尺寸变大时字号随宽高联动增长，并保留最小、最大字号边界，避免极端尺寸造成不可读或失控的排版。

### 相关实现

- `web/src/lib/canvas/canvas-text-scale.ts`：字号缩放和边界规则。
- `web/src/components/canvas/canvas-node-content.tsx`：文本节点展示与编辑态应用字号。

## 支付订单与对账导出

管理员在 `/admin/payments` 可按关键词、状态、渠道和创建/支付/入账日期筛选订单，并导出全部匹配记录的 CSV。对账支持按渠道、执行状态和账单日期导出每日汇总；单次对账明细支持按结果或“仅异常”导出。单次最多 10000 行，超限明确提示，不静默截断。文件使用中文表头和北京时间，保留完整订单号、精确金额/积分及失败原因。导出不触发查单或积分补发；对账运行中不能导出明细。具体字段和参数见 [HTTP API 合同](../backend/http-api)。

## 首页常驻滚动通知

工作台首页顶部可展示运营配置的常驻滚动通知。管理员在「运营 → 常驻通知」维护标题、类型（公告 / 活动 / 更新 / 警告）、生效窗口和跳转链接；标题支持分段样式和光标处插入 emoji。公开接口 `GET /api/banner-announcements` 只返回当前生效条目，前台轮播展示，用户可本地关闭。

### 相关实现

- `web/src/components/layout/banner-announcements-slider.tsx`：首页顶部滚动通知条。
- `web/src/pages/admin/components/admin-banner-announcements-panel.tsx`：后台配置面板。
- `GET /api/banner-announcements` 与 `/api/admin/banner-announcements`：公开生效列表与管理 CRUD。

## 工作区签到加油站

积分功能开启且后台「每日签到积分」大于 0 时，首页侧栏容量条上方固定显示领取卡片：标题为「{站点品牌名}加油站」，副文案为今日可领积分，黑色按钮「立即领取」。未领取时一直显示；当天领取成功后立即消失。关闭积分、签到积分为 0，或未登录时不显示。卡片用白底、黑按钮和青绿积分数字，不套浅蓝舞台底。

### 相关实现

- `web/src/components/layout/workspace-sidebar-checkin.tsx`：侧栏领取卡片。
- `POST /api/wallet/checkin`：每日签到入账，同一天不可重复领取。

## 工作区账号容量

登录后，首页侧栏左下角用户头像上方显示账号文件容量进度：左侧硬盘图标，右侧已用容量与总容量，进度条旁显示剩余容量。用量达到 70% 变为警告色，达到 90% 或已满变为危险色。点击进入素材库；资产页页头仍展示同一用量。收起侧栏时保留图标和细进度条，悬停可看到已用、剩余与总容量。统计包含素材文件和 Agent 会话附件。

### 相关实现

- `web/src/components/layout/workspace-sidebar-storage-meter.tsx`：侧栏容量进度。
- `web/src/pages/assets/asset-storage-usage.tsx`：资产页同一查询。
- `GET /api/resources/storage-usage`：账号已用字节与配额总容量。

## 云端 Agent（写入与生成仍待真实环境验收）

云端画布 Agent 已分离行为策略、用户目标、参考事实和运行状态。续聊保留已送达插话，不再继承代码预设的创作自由；旧待办只作上下文，可移除取消项，催办不会强制工具调用或无限重复。提示词来源与发布约束见[画布 Agent 提示词与用户意图](/docs/backend/agent-prompt-policy)，真实模型行为仍待场景验收。

## 画布 operations 同步与本地恢复

画布内容按字段和对象生成 operations，节点、连线和顶层业务字段分别提交；平移、缩放等 viewport 只保存在本地。每次请求携带唯一 `mutationId` 和可选基线版本，服务端在同一事务中校验对象存在性、字段基线、资源归属并保存回执。可选顶层字段不存在时用 JSON `null` 表示，避免 `undefined` 被序列化为缺失属性。相同请求安全重放，响应丢失、断网、刷新或服务端暂时不可用时，浏览器保留已确认基线与未确认请求，后台使用原 ID 和原 payload 自动继续处理。结构化配额只聚合当前用户素材与画布数据，不扫描任务和 API 日志大字段，容量上限与事务语义不变。

不同字段的并发修改可以合并；同一字段或同一对象的基线不一致会返回冲突，当前本地修改继续保留。删除后的迟到节点、连线或媒体更新不会重新创建对象，只有显式新增 operation 可以创建实体。界面只显示同步状态，不提供版本记录、加载云端版、覆盖云端或手动恢复入口。

此合同不提供多人实时协同；它保证局部变更、幂等重放和删除保护，避免旧缓存静默覆盖新内容。内部历史表仍用于资源完整性维护和审计，不作为用户编辑入口。

相关实现见后端 [画布 operations 同步](/docs/backend/canvas-operations-sync)、`web/src/services/user-data-sync.ts`、`web/src/services/api/user-data.ts` 和 `web/src/pages/canvas/canvas-sync-status.tsx`。

### 管理配置与稳定性

后台“平台配置 → 电商画布”提供电商创作总开关、详情/主图/模特上身/种草四种用途、模特库及自动装订开关。四种用途分别配置默认分析指令，优先级为用户自定义 → 后台默认 → 内置版本。配置点击保存生效，支持撤销、刷新覆盖保护、离页保护及上一版载入草稿。它控制业务入口和套图流程，不替代模型权限、账务和额度管理。

公共模特可维护名称、标签、启停和多角度参考图；启用至少一张图片。用户在模特库中导入已发布记录，图片和记录复制为自己的私人素材，之后后台停用不删除私人副本。

电商创作表在画布内即时保存编辑，分析显式接收当前行数据；四种用途各自保存方案。生成结果记录商品、用途、运行归属，其他商品的同名槽位不影响布局。自动装订按运行加锁且始终释放，旧回调不清除新计划；失败后可以重试装订或取消，重试不重新生图。同一商品保留一个待装订计划，完成或取消后可发起下一轮。交付按原图像素与文件体积校验，无法检测的项目显示“未检测”。节点关系改为每次画布快照建立共享索引，减少各节点重复扫描；尚未完成细粒度订阅和浏览器性能基准。

**电商画布与自由画布互不影响。** 画布有 `kind`（见 `web/src/lib/canvas/canvas-kind.ts`），缺省是自由画布。两个方向的隔离都由它决定：

- 十三个电商节点**只在电商画布里出现**——自由画布的右键菜单、连线菜单、工具栏都看不到它们
- 预演台、分镜脚本、角色卡、音频反过来不进电商画布——商品图不需要 3D 场景
- 画布上那颗「风格」按钮在电商画布里换成**拍法**（白底主图、真实种草图、模特上身图、高级海报），预设也换成电商那批（商品一致性复述、详情页单屏、信息图底图、长图）

**节点清单是查漏表，不是节点名列表。** 一套上新有几十个节点，用户扫这张表是为了找东西和查漏，所以电商画布里它换了一套说法：

- **按工作流阶段分组**（商品与约束 / 拍摄与成图 / 参考与拆解 / 成片与交付）——画布上节点本来就是按阶段铺开的，清单按同一顺序排，两边的空间位置与列表位置能对上
- **摘要说「能不能往下走」**：商品报档案 2/4 项与视角数、拍法报几张清单与有没有整组要求、卖点报几条缺依据、交付报商品编码与投放平台、产物图报有没有认领清单行……不再是「商品节点 · 800×800」
- **有问题的点一个标记**：拦截项是三角、待补是圆点，颜色分档
- **「只看没配齐」筛选** + 头部报出待补数量与正在生成的数量
- **缩略图用各自的图标**——商品/拍法/信息图/交付在一列里长得一样，等于没缩略图

判断一律复用各领域模块自己的函数（`ecommerceProductReady`、`ecommerceShotSetReady`……），不在清单里重写一遍规则——两份规则一定会分叉，然后清单说的和卡片说的不一样。

**节点菜单按分组呈现。** 添加节点菜单原来是二十来项平铺成一张四列网格，连线菜单是一条 22 项的平铺长列——找「A+ 内容」得把整片扫一遍。现在两边都有分组标题，标题本身就是导航。

理由：两边的节点集不是同一个产品的子集，是**两套工作流**。自由画布上摆一个「商品」节点，用户会以为要先填商品档案才能出图；电商画布上摆「预演台」，用户会以为要搭 3D 场景。混在一起不是「功能更多」，是把两条流程的入口都搞模糊了。缺省按自由画布处理——宁可少显示电商节点，也不该把它们漏进自由画布。


**节点不预铺，入口收成一排套图按钮。** 新建电商创作画布时只有一个商品节点——它是唯一的必需输入。另外十二个电商节点（拍法 / 卖点 / 文案 / 风格 / 排版 / 信息图 / 复刻 / 拆解 / A+ / 视频 / 改稿 / 交付）暂时从右键菜单和连线菜单里去掉：原因不是它们不好，是**它们把「一步能做完的事」拆成十几个节点让用户自己接**——铺九屏、连文案、连排版、逐张点生成、等九张出完、再逐张叠字、再拼长图、再切片。每一步都「可配置」，合起来是一条没人走得完的流水线。节点实现全部保留，老画布照常渲染。

商品节点上现在是一排套图入口，各自对应一套行业标准交付物与一个画幅：

| 入口 | 出什么 | 画幅 | 装订 |
| --- | --- | --- | --- |
| 一键详情页 | 九屏金字塔，从痛点共情到售后保障 | 3:4 | 出完拼长图并按平台切片 |
| 一键主图 | 核心展示 / 卖点 / 场景 / 细节 / 规格 | 1:1 | — |
| 一键模特上身 | 正面全身 / 半身细节 / 背面 | 3:4 | — |
| 一键种草秀 | 封面 / 场景 / 上身 / 细节，求真实感不求精致 | 4:5 | — |

点开任何一个，会在商品右侧创建并连接对应的**创作表节点**，一行一张图。同一商品再次点击同一用途时定位已有表，不重复创建。分析、逐行编辑和批量出图直接在节点内完成，不打开套图弹窗。电商画布保留普通创作表入口，也可手动连接商品来启用电商工作流；已有行提示词保留。出图结果连接到创作表，并保留商品约束引用。

### 商品输入与参考图

商品卡片只保留改名、商品视图、参考图、模特选择和四个套图入口，不再提供重复的商品档案、SKU 或物料方案编辑面板。「整组统一」与「按行业套路铺底」入口已移除；每张图的要求集中在套图面板的分析指令和逐行提示词中编辑。

商品视图有正面、侧面、背面、细节、包装五个缩略图槽位。把图片节点连到指定槽位的连接点，用 `product-view:front`、`side`、`back`、`detail`、`packaging` 区分视图，而不是只按图片连入顺序判断。参考图使用独立的 `visual-reference:<编号>` 输入与同样的缩略图控件，和商品视图分开显示。每个槽位可预览、替换或断开图片；空槽可上传图片。连接点位置随商品节点与槽位尺寸变化重新测量，缩放和调整卡片大小后的实际交互仍待用户验收。

模特库展示用户私人记录和管理员已发布的公共模特；生成图片可从右键菜单加入私人模特库，新建模特或补充参考图。管理界面支持名称与标签搜索、排序、改名、参考图上传与预览、设置封面和批量删除；删除库记录不删除原始图片。账号切换、持久化与真实生成链路仍待用户验证。

### 套图面板：一张图一条提示词

前面几版让模型写的是每屏的一句话文案（标题 + 正文），然后指望编译时把它拼进提示词。那是错的：**文案只是图上那几个字，而每张图真正要的是一条能直接出图的指令。** 主图画什么、模特上身图画什么、细节图画什么，三者的构图、光线、景别、有没有人全都不一样。

所以面板里的单位是「一张图一条完整提示词」，四列：屏次 / 这一张要什么 / 提示词 / 结果。提示词那一列是主角，占走大半宽度、三行高、可换行；没填的行整行降一档亮度、输入框变虚线，九行扫下来一眼看见缺哪张。**表里没有的图不生成。**

三件事按顺序：

1. **选分析模型 → 分析商品。** 分析模型要能看图（选择器只列支持图片输入的文本模型），它读你连进来的商品实拍 + 商品档案，为每一张写一条提示词。一条提示词里必须说清四件事：画面主体与状态、场景与背景、光线与镜头、图上文字（要的话逐字用引号写进去）。提示词里反复强调**不要把同一套描述复制到每一张**——模型偷懒时会给九屏写出九条几乎一样的提示词，出来的就是九张一样的图，而用户要等九次生成才发现。

**这段提示词可以改，而且改过就一直用。** 工具条上一个「分析提示词」，点开是一整段可编辑的文本，默认那一份就是上面这套要求；旁边一个「导入文件」能读 `.md` / `.txt`（自己攒的模板、从别处拿的 skill 文件都行，读进来先看一眼再决定用不用）。拆法是**「怎么写交出去、写哪些留下来」**：用户改的是导演指令（怎么写、忌讳什么、店里那套说法）；商品事实（你填的档案）、屏次与职责、输出格式由系统追加在后面——那三段不是写法而是任务本身，少了任何一段，自定义的提示词都会产出解析不了的东西，而用户不会觉得是自己少写了格式，只会觉得功能坏了。

改过的分析指令随当前创作表保存，四种用途独立维护；未自定义时使用后台默认指令，再回退到内置版本。「恢复默认」清除当前表对该用途的自定义指令。

**屏数不固定，表说了算。** 「屏次」与「这一张要什么」两列直接可改，底部「加一屏」，每行可排序、可删。行业套路给的九屏只是起点——想拆成十二屏就加三行，想只出六屏就删三行；也可以在导演指令里要求不同的分工，模型返回几行这一套就是几行。**顺序不是装饰**：出图按表的顺序提交，装订长图也按这个顺序接，「先讲痛点还是先摆参数」就是详情页的叙事。

**Skills 来自用户技能库。** 分析模型工具条旁的 Skills 选择器使用已加入的技能列表，刷新与打开 `/skills` 的入口紧邻选择器。分析提示词的文件导入仍用于编辑个人指令，不等同于加入技能库。所选技能文件是否真正进入分析请求、增删技能后的刷新与失效技能反馈，仍待真实请求验收。

**装订可以关。** 详情页默认出完自动拼长图并按平台切片；关掉之后出图照出、只是不拼。商品卡片不再保留重复的手动装订入口。
2. **逐条核对、改。** 表里的字不编；改哪行改哪行。可以先分析商品，也可以直接填写每行的完整提示词；不再提供行业预设一键填充提示词的入口。
3. **选出图模型与参数 → 出图。** 底部三样：出图模型、尺寸与画质（按模型能力自动只显示它真支持的档位，带价格守卫）、以及出图按钮本身。整批一次提交（「批量生成 N 张」，复用画布的批次队列：并发上限、失败重试、任务对账），或者**只出某一张**——每一行的结果格上挂一个「出图 / 重出」按钮，只铺、只出这一张，不动其他八张，面板也不关。

每一行的提示词原样写进对应节点。重出保留旧图，并为当前商品和槽位建立新结果；结果记录商品、用途和运行归属。既有节点需要同步生成参数时使用 `synchronizeGenerationSpec`，防止旧生成合同盖住当前提示词。

**分析和出图是两个模型，所以创作表上有两个选择器。** 分析要读图、出图不用，两者常常不是同一个模型。选完存在当前创作表节点上，互不干扰；首次创建表时接续商品原有的模型、参数与用途草稿。

**节点在出图时才铺，只为表里有提示词的行创建结果。** 重出保留旧图，按当前商品的同槽位历史数量向下摆放新结果；不统计其他商品的同名槽位。当前面板默认展示较新的结果，显式选择采用版本仍待后续完善。

**一条提示词都没有时不给「只出有的」。** 那等于出 0 张——面板关掉、画布上什么都没发生，用户只会以为按钮坏了。空表时弹的是「去补提示词」，点了留在面板里。同理，这条链路上每一条提前退出的路都要说话：静默 return 是「点了没反应」这类 bug 的成因。

**不再挂通用拍法清单。** 每一张的拍法已经写在那一张自己的提示词里；再挂一份 `ecommerceShotSet`，编译时它会作为「本张：构图…光线…」前置到提示词之前，与用户核对过的那条打架（用户改成俯拍，清单还写着平视）。独立的拍法节点那条路（用户自己排的清单）照旧。

### 既有商品档案与 SKU 数据

商品卡片不再展示档案、变体轴和物料方案编辑器。已有商品档案与 SKU 数据仍保留在领域数据中，本次 UI 清理不删除用户记录；原有占位符编译能力不等同于当前卡片仍提供变体编辑入口。后续批量铺货工作流应单独验收。

### 拍摄清单：一套交付物一个拍法节点

一次上新出的是成套的图，这些图之间的差异是**清单上的行**，不是彼此独立的节点。把五张主图拆成五个拍法节点，用户要填五遍几乎一样的表，还得在画布上四处找哪一份对应哪张图。

所以拍法节点装的是**一张拍摄清单**：整组统一要求写一遍，每行一张图（用途、构图、光线、色彩、镜头、背景、文案位、排除）。产物图片节点带 `ecommerceShotId` 认领清单里的一行，生成时只展开那一行——把五行要求全塞进一次生成，模型会试图在一张图里同时做到五件事。

清单多行而某张图没认领时只输出整组统一，不猜是哪一行；卡片上会标出「未认领」的行。

### 十三个电商创作专用节点

生成时按**从硬到软**的顺序编译进提示词：商品锁定 → 复刻参考 → 竞品参考 → 品牌风格 → 商品卖点 → 文案 → 拍摄方案。复刻与竞品排在品牌风格前面，因为它们是「这一张参照什么」；参照在前、自我在后，模型才不会把参考图的调性当成自己的。

| 节点 | 写什么 | 编译出的块 |
| --- | --- | --- |
| **商品** | 品类、外观、标识、禁止项（用户确认过的事实）+ SKU 变体轴 | 【商品锁定】 |
| **爆款复刻 / 溶图** | 用途（复刻爆款 / 溶图合成）+ 维度 + 强度 + 笔记；不可复刻清单是常量 | 【复刻参考】或【溶图合成】 |
| **竞品拆解** | 拆解结论 + 我方大纲（每屏标「跟着做」或「反着来」） | 【竞品参考】 |
| **品牌风格** | 色板、色调、气质、字体气质 | 【品牌风格】 |
| **卖点** | 一条条可验证的主张 + 依据 | 【商品卖点】 |
| **文案** | 标题、副文案、行动引导、价格 | 【文案】 |
| **拍摄清单** | 整组统一 + 每行一张的差异 | 【拍摄方案】 |
| **排版** | 版式 + 画幅，把文案叠在成品图上 | 【文案】（逐字交给模型）|
| **信息图** | 标注 + 引线 + 规格表（含尺码表） | 【信息图】（逐字交给模型）|
| **电商视频** | 镜头表：每镜用哪张图、停多久、怎么动、什么字幕 | 【电商视频】 |
| **改稿** | 一张图的版本链：每版改了什么、从哪一版改的 | 改动说明即提示词 |
| **A+ 内容** | 亚马逊的八个模块槽位，每块带硬性尺寸与字数上限 | 【A+ 内容】（每块单独出图）|
| **交付** | 商品编码 + 版本 + 平台目标，汇总上游校验并出清单 | 不进生成提示词 |

### 两条出图路径：提示词优先，本地合成为辅

**主路径是提示词走 API 模型。** 所有电商节点都把自己那份结构化配置编译成提示词，交给模型出图出片——与项目里其余所有生成共用同一条链路（批次队列、失败重试、任务对账、技能注入都不另起一套）。

| 节点 | 主路径 | 备用路径 |
| --- | --- | --- |
| 拍摄清单 | 「生成整组 · N 张」按清单逐行出图；每行还有独立的出图按钮 | — |
| 爆款复刻 | 「生成复刻图」把复刻公式与商品锁定一起交给模型 | — |
| 信息图 | 「生成信息图」把标题、标注、规格表逐字交给模型 | 「本地精确合成」按真实字体排版 |
| 排版 | 「生成成品图」把文案与版式交给模型 | 「本地精确合成」按像素排字 |
| 电商视频 | 「生成成片（N 秒）」把镜头表交给视频模型 | — |
| 改稿 | 「生成 vN」把改动说明交给模型，当前版自动作为参考 | — |
| A+ 内容 | 每块一个出图按钮，按自己的尺寸单独出图 | — |
| 交付 | 「一键详情页」把一屏一屏的图拼成长图并切片 | — |

备用路径只保留一处：**文字必须逐字准确时**（价格、参数、认证编号）。模型偶尔会写错一个字，而上架图错一个字就是事故——这时走本地合成，图和字都按用户设的像素排，一个错字都不会有。这是取舍，不是能力缺失：模型渲染省一道工序但改字要重出图，本地合成能秒改但成品不经过模型。

**约束链决定商品一致性。** 生成时沿连线向上走最多六层电商节点，把商品锁定块、品牌风格、卖点、文案、拍摄方案一起编译进提示词。连线菜单里单独补的节点也走同一条链——所以「只出一张主图」和「出一整套」用的是同一套约束，不会因为节点少就丢掉商品锁定。


### 电商视频：把一套图编排成片

视频在电商里已经和图片平级：淘宝主图视频权重高、审核不过就不展示；抖音商品视频是流量入口；亚马逊品牌备案后是「6 图 + 1 视频」，视频直接进图片轮播。

和内容创作视频的区别在于：**电商视频有硬性规格，而且素材是现成的**。一套图已经出好了，视频要做的不是「从零生成」，而是**把已有的图编排成片**——哪个镜头用哪张图、停多久、怎么运动、配什么字幕。

所以视频节点的主体是**时间轴**，不是表单：格子的宽度按时长分配，用户扫一眼就知道哪个镜头太长、整体节奏对不对。这是视频和图片最不一样的地方——图片看单张，视频看**节奏**，而节奏只能靠时间轴表达。

平台规格在生成前就卡，不等到上架才发现：

| 平台 | 比例 | 时长 | 关键限制 |
| --- | --- | --- | --- |
| 淘宝 / 天猫 | 3:4 / 1:1 / 16:9 | 建议 15s，最长 60s | **9:16 上传后商详不展示**——别把抖音那版直接搬过来 |
| 京东 | 1:1 / 3:4 | 15–60s | 首帧需为商品画面，不要纯色开场 |
| 抖音（抖店） | 9:16 | 3–60s | 首帧禁止二维码、第三方 Logo 与夸大对比图 |
| Amazon | 16:9 / 9:16 | 1–12 分钟 | 不要黑边与幻灯片式剪辑；静音也要看得懂 |

从一套图铺镜头时，总时长超上限是**按比例压缩**而不是砍掉后面的镜头——砍掉会让「一套图」不完整。

**八种爆款结构**（痛点解决 / 开箱种草 / 产品演示 / 产品口播 / UGC 种草 / 反应展示 / 带货短剧 / TVC 广告）做成**分镜骨架**而不是风格标签：每种给出一段段的结构（第几秒做什么、建议时长、这一段解决什么、用什么运镜），点一下铺成镜头表，卡片上的结构条按秒数分配宽度，一眼看出节奏。

为什么必须是骨架：视频的成败在结构。同一个商品用「痛点解决」和用「开箱种草」拍是两条完全不同的片子——前者先共情再给方案，后者先给悬念再揭晓。只给一个「痛点风格」的标签，模型不知道先讲什么。TVC 更是和其余七种**正好相反**：不留钩子、不喊卖点、节奏慢，用画面完成度说话。

**爆款视频复刻**：连一段爆款视频进视频节点，拆它的节奏、切点、运镜与段落结构，再换成自己的商品。三种模式（留主体换场景 / 留场景换主体 / 只借结构）。

硬边界比图片侧更严，而且**音乐排在第一**——视频平台的音频指纹稽查比图像指纹更成熟，搬音乐是直接侵权；人物面孔、品牌标识、画面素材同样不能搬。

### 溶图合成：同一个节点，两种相反的约束

复刻节点有**两种用途**，约束正好相反，所以必须分开：

- **复刻爆款**：参考图是别人的图。抄画面是侵权，所以不可复刻清单是硬边界，模型要「借结构、换画面」
- **溶图合成**：参考图是**自己的**场景图或模特图（实地拍的、图库买的）。这里没有侵权问题，反而要**尽量贴合**——光线方向、透视、色温、接触阴影、倒影、边缘环境光，六项逐条写进提示词

合并成一个模式是错的：同一句「不要照搬参考图」在溶图里会把场景也丢掉。模型在溶图上最常见的错是给商品单独打光，于是它浮在场景之上——所以「接触阴影」与「倒影」是这一块最要紧的两条。

用途决定整段提示词怎么写，所以它排在编辑区最前面；选了溶图之后，复刻强度与复刻维度整块隐藏（它们在这里没有意义），笔记与排除项的措辞也跟着换。

**视频提示词反推**：和图片反推的区别在于要拆的是**时间结构**，不是画面描述。指令明确要求按秒输出段落、标出切点与运镜，并禁止描述画面内容——画面本来就要换掉，描述它对复刻毫无用处。

**跨境多语言**：七种目标市场语言（中英日韩西葡阿）。语言不只影响字幕文字——同一支片子给不同市场看，卖点排序也该变（欧美重参数与认证，日本重细节与售后，中东注意阅读方向为右起）。

### 改稿：版本链，不是撤销重做

调研里排第一的缺口，也是最不像「AI 功能」的一个：设计师 80% 的时间在改，而 AI 工具 80% 的能力在「生成」。更糟的是改稿**没有版本记录**——运营说「回到上一版」，设计师只能凭记忆重做；文件名排到「最终版2打死不改版」。

改稿节点做两件事：记清楚每一版**为什么存在**（改动说明是必填项，不是备注），让版本**可追溯**（从哪一版改的、改了什么、哪一版在采用）；以及**按改动说明出下一版**——改动说明本身就是提示词，当前版的图自动作为参考。

版本链与出图之间靠一条规则对上：写了改动说明、还不是当前版的最新一版就是「待生成」，按钮显示成「生成 v3」。没有待生成的版本时按钮不给点，而不是拿当前版的说明重跑一遍——那会凭空多出一版没人要的图。

新出的图落在改稿节点**下游**，版本链同时读上游和下游的图，所以刚出的那张会直接出现在「v3 对应的图」下拉框里，不用手动再连一次线。

一条硬规矩：**版本号只增不减，禁用「最终版」。** 「回到上一版」是把旧版标成当前，**不删后面的版本**——运营可能改主意又要回来，而且它们记录了走过的弯路。

局部修改的提示词里，最关键的一句不是「改成什么」，而是「**其余部分必须逐像素保持原样**」。没有这句，模型会顺手把整张图重新画一遍——这正是「西瓜对了背景又崩了」的成因。

### 一键详情页：长图 → 切片 → 能直接上传的片

平台限制的是**单图尺寸**，详情长图必须切成多张上传。这一段原本全靠人肉：拼图软件拼长图、手动量切点、导出时还要人眼避开切穿商品。

交付节点上一个按钮做完：按连线顺序把上游的图拼成一张长图 → 按平台单片上限规划切点 → 逐片导出。切点优先落在**屏与屏之间**——那里天然是模块边界，切穿了也不伤商品。所以拼接时先记下每屏的纵向区间，作为保护区间交给切片算法；算法把等分切点往上挪到最近的屏边界，挪不动的记进 conflicts 并在卡片上说出来，不静默接受。

拼长图与切片都是**纯装配，不经过模型**：九屏图已经出好了，交给模型它只会重画，商品就不一致了。产物直接落成画布上的图片节点——长图一张（看整体）、切片各一张（拿去上传），切片标题直接用交付命名，上传时照抄文件名就行。

### 尺码表：服装退货率的头号原因

国内头部 AI 工具集体没做深的一块。尺码表与设计工作流是割裂的——美工还是「去尺码工具做图 → 下载 → 放进详情页」。

影策把它收进信息图节点（第七种骨架）：按品类给标准量体项（上衣 / 裤装 / 裙装 / 鞋靴 / 童装 / 箱包），列名自带单位，并附**量体位置说明**——买家不知道自己该量哪里，是尺码表失效的真正原因。

编辑界面是**网格**而不是通用的两列表格：五个量体项 × N 个尺码，两列编辑器填不了。列头带单位（不带单位的尺码表是最常见的返工原因——买家分不清 38 是厘米还是码数），每个格子悬停显示怎么量。量体说明会自动进底部信任条。

### A+ 内容：亚马逊的模块化版式

A+ 不是「一张长图」，是**一组带硬性尺寸的槽位**。图放错尺寸会被审核拒，文字超字数会被截断。八个常用模块的规格直接写进校验：图文叠加 970×300（推荐 1940×600）、标题 ≤70 字、正文 ≤300 字；对比表最多 6 个商品、10 行、单元格 ≤250 字、商品图最小 150×300。亚马逊官方数据：基础 A+ 提升销售最多 8%，优质 A+ 最多 20%。

卡片主体是**模块清单**，每块一行，行上带它自己的尺寸与字数——A+ 的难点不在写文案，在「有哪几种槽位、各自什么规格」。模块库常驻可见，点一下加一块。

**每块单独出图**，不是整份一次生成：不同模块的画面尺寸差着量级（品牌头图 1940×600、四图一文 220×220），一次生成把两种尺寸混在一起，模型只会给出一张两头不讨好的图。文字不进画面——A+ 的标题与正文由亚马逊自己的叠加层渲染，画进去会和叠加层打架。

### 详情页长图切片

平台限制单图尺寸，详情长图必须切成多张上传。切点在模块边界上，**不能切穿产品主体**——切穿了上架后每张图都缺一块。

这一层算切点方案（实际裁像素走 canvas）：按平台上限等分，再把每个切点挪到最近的安全位置，优先挪到保护区块上方。挪不动的切点记进 conflicts 而不是静默接受——工具不该替用户吞掉这种问题。

### 让助手起草：把「填表」变成「核对」

调研里这一块是明确的缺口：用户连入商品图之后，商品档案、卖点、文案全是从空白输入框开始写。而助手已经能真实读图（`canvas_inspect_image`）也能写节点字段（`canvas_apply_ops` 的 patch），缺的只是**入口**。

商品、卖点、文案、品牌风格四个节点各有一个起草入口，点一下就把节点与一条准备好的指令交给助手。每条指令都带同一条硬约束：**模型猜出来的必须标成待确认，不能直接当成事实。**

商品锁定块是整个电商创作的信任基础——用户敢说「这就是我那件商品」，靠的是那段字逐字来自他的确认。把模型从图里猜的结论直接写进去，比留空更危险：生成出来的图会带着一个没人确认过的「事实」，而且越生成越跑。

起草卖点的指令明确要求：想不出依据的把依据留空并标出来，不要自己编数字或认证；起草文案的指令明确不写价格——价格必须来自真实定价。

### 交付：出图之后到上架之前

调研里最一致的发现：AI 工具在「生」上卷得厉害，但设计师的钱和时间花在改、套、配、审、名、装、传上。这一段目前全靠人肉——命名规范是纯 SOP 教育，版本号靠「最终版 / 最终版2 / 打死不改版」，平台校验是事后独立扫描，而不合规会直接导致 listing 被压制。

交付节点把这一段收进画布：汇总上游的图 → 逐张按平台校验 → 按「商品-用途-版本-变动」命名 → 导出一份带 BOM 的交付清单 CSV（不加 BOM，Excel 打开中文是乱码，这一条是交付件能不能用的分水岭）。

版本号**只增不减**，不提供「回到上一版」——回退由保留旧文件实现。

### 爆款复刻：复刻公式，不复刻画面

美图、稿定、摹小仙、绘蛙、即创五家头部同时押注这件事，形态已经标准化：**双输入**——参考图给结构（构图、布光、配色、版式、道具、氛围），商品图给主体。

一条硬边界：抄画面是侵权，平台有图像指纹稽查。所以「绝对不复刻」清单（品牌标识、模特面孔、原创文案、参考图画面本身）是**常量，不可编辑**——用户把它清空不该是「设置」，是「事故」。清单排在复刻强度前面，因为模型读到「贴近」会倾向于照抄。

### 竞品拆解：拆的是结构，不是画面

头部工具全都只做到「风格复刻」，输出的还是一张图；运营真正要的是**结构**——竞品第一屏讲什么、卖点按什么顺序排、信任背书放在第几屏、用了什么证据类型。

拆解节点连一张竞品图，按勾选的六个维度（页面结构、卖点顺序、证据类型、信任模块、版式层级、配色体系）让模型读图，输出结论 + 我方大纲。拆解指令明确要求**只描述结构、不复述文案**——复述竞品原文会把别人的文案带进我们的提示词。

大纲每行可以标「跟着做」或「反着来」。标了「反着来」的行不会进提示词，它标记的是要和竞品拉开距离的地方——拆解的目的从来不是照抄，是找差异化的位置。

### 信息图：文字必须逐字准确的一类图

主图、场景图、种草图的文字交给排版层留位就行。信息图不行——它的全部价值就在那些字上：参数、尺寸、材质、卖点。数字写错一位是虚假宣传，字糊成一团就是废图。

默认走提示词：标题、标注文字、规格表**逐字进提示词**，附一条硬规矩——「表格里的数字与文字必须与上表完全一致，不得改写、四舍五入、补充或增删行列」。标注位置用**方位词**（左/右）而不是坐标：模型读得懂「标注框在画面右侧」，读不懂百分比。

文字错不起时改走「本地精确合成」：标注、引线、规格表在浏览器里按真实字体排版。这是取舍的另一头——不过模型，所以一个错字都不会有，代价是改一个字要重新合成一次。

六种骨架：卖点标注、尺寸标注、材质分解、规格对比、包装内容、参数表。三条行业硬规矩直接写进校验：一张图只讲一件事（标注最多 5 条，超出即拦）、2000px 画布上正文不小于 32px、对比表里点名竞品即拦。

### 排版：文字一层，出图两条路

竞品全部把字烧进图里，所以价格从 199 改成 159 就要重出整张图。影策把文字做成独立的一层叠在生成图上：

- 预览期间一直是 DOM 叠加，**改一个字立即生效**，不重新生成、不重新合成
- 「生成成品图」把文案与版式交给模型（主路径）；「本地精确合成」按像素排字（文字错不起时用）
- 版式用「九宫格锚点 + 占短边百分比」表达，所以同一套版式天然适配任何画幅——**一次编辑，1:1 / 4:5 / 3:4 / 9:16 / 16:9 / 2:3 各出一张**，主体和文案位跟着变
- 版式库有 6 种（底部信息条、顶部横幅、价格角标、侧边留白、详情页单屏、海报居中），每个文字块的位置、字号、字色、垫底色、加粗都能改
- 文案为空的块不显示，也不留空

### 一次出一套，或者只出一张

套图面板底部一个「批量生成 N 张」：表里每一行的提示词写进对应节点，整批进画布的生成队列（并发上限、失败重试、任务对账复用已有的批次机制）。缺提示词的行会先问一句「还有 N 张没有提示词」，可以选择只出已经有提示词的那几张。每一行的结果格上另有「出图 / 重出」，只出这一张。详情页九屏出齐后自动拼长图并按平台切片。

### 接 Agent 与技能

十二个电商节点都注册进了后端能力注册表，所以画布助手能像操作分镜脚本、批量创作表那样操作它们：

- **能发现**：`canvas_list_node_types` 会列出这十二种节点及其连接约束
- **能读**：`canvas_get_state` 精读商品档案、拍摄清单、卖点清单、文案、品牌风格、信息图、复刻配置、拆解结论、交付配置。投影器递归保留文本与画布节点 ID，丢弃 URL、storageKey、正文和任务状态
- **能建**：`canvas_apply_ops` 的 `add_node` 可创建这十二种节点
- **能改**：商品档案的品类/外观/标识/禁止项与五个视角绑定、拍摄清单的整组统一要求、文案的四个字段、品牌风格的色调/气质/字体气质、信息图的标题与信任条、复刻的强度与结构笔记、交付的编码与版本，都可经 `canvas_apply_ops` 的 `update_node` 写入

助手侧配合已有的 `canvas_inspect_image`（真实读图）就能做到「读一下这张商品图，起草商品档案」——把图片数据交给模型，模型填写品类与外观，用户核对。**外观字段必须来自用户确认的事实**，能力卡里明确写了：把模型从图片猜出的结论直接写入，比留空更危险。

技能库已有 `ecommerce` 类目，生成时经 `skillRuntime.prepare()` 注入提示词——电商节点走的是同一条生成链路，所以技能本来就能用。

### 其余几个刻意的设计

- **商品节点不做抠图、不做蒙版、不建模。** 商品长什么样完全靠锁定块那段文字压住，逐字进提示词。
- **商品节点连入商品实拍后按正面/侧面/背面/细节/包装指定视角**，这些图会被补进参考图，且不占用户自己连的参考图槽位。素材越全，能拍的角度越多。
- **约束链可以串联。** `商品 → 拍法 → 图片` 这种连法里，图片节点隔着拍法也能拿到商品——沿约束链上溯 6 层，碰到产出媒体的节点就停。只认直接入边会让连线看着对、结果却少了锁定块。
- **卖点的依据是硬要求。** 没有依据的条目编译时带上"尚未提供依据，不要展开成具体数据、功效或认证"，节点里也用橙色标出。
- **图片和文字一条提示词一起交给模型。** 每张要画什么、图上出现哪几个字，都写在那一张的提示词里。上一轮做过的本地叠字那一整套（`ecommerceComposite` / `pendingComposite` / `compositeEcommerceImage`）已从一键流程里去掉——模型画不准汉字是它的问题，让用户逐条核对文字再交给它，比在图上再盖一层字强。排版节点的本地精确合成保留在编辑区里，只作为「文字错不起时」（价格、认证编号）的备用。
- **品牌风格是跨整组图统一的那一半。** 拍法决定怎么拍，风格决定看起来像谁。
- **种草图求的和主图相反。** 主图求「精致 + 信息密度」，种草图求「真实感 + 场景感」——产品太突出、太像广告，在内容平台就被划走。所以种草与买家秀的拍法全部是「不像拍出来的」：桌面随手拍、对镜自拍、外出打卡，排除项里明确写着影棚感、摆拍痕迹、过度精致。

拍法库有 33 种起始拍法，分九组（基础、场景、细节、展示、信息、营销、内容、信息图、海外）；品牌风格库有 6 种预设（极简白、轻奢深色、自然有机、活力快消、复古胶片、科技冷感），每个带可核对的十六进制色板。两者在节点里都以分组胶囊展示，点一下就载入，载入后每个字段都能改。

交付物库有 9 套（主图 5 张、详情页 9 屏、种草图 4 张、买家秀 3 张、信息图 5 张、海外 Listing 7 图位、主图视频 4 镜、轮播视频 5 图、整套上新物料 16 项）；平台规范覆盖 10 个平台，含 4 个平台的视频规格与 4 个平台的详情页切片上限；信息图有 7 种骨架，尺码表覆盖 6 个品类，A+ 覆盖 8 个常用模块。

## 批量创作表

批量创作表每行是一项任务，每个参考图格子绑定一张图片；同一行可通过多个参考图列使用多张图。点击格子可选择画布图片或上传，也可把图片连线接到指定格子。已有图片替换前确认，清除格子保留源图片节点；保留列排序和表内跨行、跨列交换。

左侧 1、2 等列端口直接生效：一张图片供该列各行共用，多张图片按连接顺序分配。单格更换或清空后成为独立配置，不被列变化覆盖；“按列填充”可在确认后恢复已连接列的统一配置。列同步只更新参考图，不重建任务行；AI 文本列表创建的表格保留独立行、动态文本列和原有生成流程，未开放普通文本节点直接连入批量表。

顶栏、普通表头、行号和非交互留白均可拖动整表；输入框、参考格、按钮、列排序和原生滚动条保留各自操作。表内支持文字拖选、内部滚动、底部添加和在指定行下方插入。放大编辑与行内编辑使用同一份提示词。全局提示词非空时统一覆盖各行的生效提示词，清空后恢复各行原文；界面显示实际生效来源，Agent 的 `set_global_prompt` 和 `generationPreview` 沿用此规则。“批量换装”和“创意生图”的预设保留。

任务入队时保存提示词与参考资源快照，排队期间修改或旋转源图不会改变已提交的输入；旧结果在输入变化后标记“输入已变更”，由用户决定是否重新生成。超过 20 行时仅挂载可见行、附近行及正在编辑的行，减少大表 DOM 和重绘开销。最终浏览器联调与性能验收见[待测试](/docs/progress/pending-test)。

## 图片尺寸与方向

图片节点按原图比例确定显示尺寸，可用角点调整大小或打开图片预览。普通滚轮保留原画布操作；单选一张未锁定的普通图片后，按住 Ctrl 滚轮可等比例改变其显示尺寸，鼠标移到画布空白处仍作用于选中图片。连续滚动合并为一次撤销和保存，不重采样图片或改变生成参数。编辑框、表格内部、多选、锁定、图层图片和只读页不进行这种尺寸调整；触控板捏合仍操作画布。

在原图工具中选择“向左转 90°”或“向右转 90°”，首次会保留原图、自动创建已经旋转的编辑副本，并连接和选中它。副本顶部保留左右转按钮，之后在同一副本上继续旋转或恢复创建时的方向；也可提前用“创建编辑副本”。

旋转生成实际图片资源，副本的下载和新提交引用使用校正后的方向；原图及其既有引用保持原样。引用编辑副本的格子会随副本更新，已入队任务仍使用提交时的快照。原方向与已生成方向保留，重复切换可复用资源。锁定、只读或尚在上传的图片不能旋转；此入口不提供任意角度或镜像操作。节点工具组菜单使用统一宽高限制，长说明单行显示并保留完整悬停说明。

工具栏根据侧栏以外的实际可用宽度收起次要操作；节点编辑面板根据剩余高度调整位置或内部滚动，避免遮住底部控件。未选择显示模式时，窄于 1024px 的窗口默认使用专注模式；用户明确进入或退出后，窗口变化与刷新保留该选择。

任务类型有三档：`try_on`（批量换装）、`creative`（创意生图）、`product`（电商创作）。`product` 面向电商物料产出：同一件商品的多视角实拍连到同一行作为参考，默认提示词先写商品锁定块（形状、颜色、材质、图案、结构、数量、标识文字不得改写），再写主图拍摄配方（构图、背景、布光、留白）。只有一张商品图也能直接生成；输出节点标题前缀为“商品”。

## 提示词放大编辑

图片和视频节点的提示词面板支持放大编辑：窗口默认约 `min(1200px, 92vw)`，编辑区最小高度 200px，右下角可对角拖拽，方向键可微调。切换节点后尺寸恢复默认，节点上的紧凑面板外观不变。

## 画布抓手与框选

画布底部主工具栏用一个胶囊开关切换「区域选择」和「抓手工具」。默认是区域选择，空白处拖动框选节点；切到抓手后拖动平移画布。按住空格或中键仍可临时平移，不改变当前工具。

框选多个节点后，悬浮栏默认提供对齐、等距、创建分镜组和批量连接。右键选区或画布空白处可「自适应整理画布」，按当前相对布局加大边距，而不是重排成宫格或媒体泳道。

## 完整 AI 拆图工作流

图片节点的 AI 拆图可先用支持视觉输入的文本模型规划图层，再选择专用拆图模型，或用普通图片模型分别重建背景与前景。规划发送经过资源归属校验的实际像素；规划结果校验图层数量、区域与提示词，失败保留可修正的错误。

生成结果组成同尺寸图层组，支持展开、显隐、合成预览、复制、删除、失败重试和刷新恢复。前景可按需去背景，Image Tools 强制输出 PNG；透明内容可按有效区域裁切并另存为独立素材。派生图片使用独立资源与素材标识，避免覆盖原图或其他图层。

规划、生图及可选去背景沿用已有任务与计费；本地合成、显隐和素材裁切不调用生成模型。普通生图是语义重建，不能保证与原图逐像素一致。图层数、像素与输出比例受前端限制，供应商失败如实显示。

## 图片节点多角度、宫格切分与多选框

图片节点「多角度」使用贴在节点下方的 3D 编辑器（天空盒/摄像头、常用角度、方向箭头），拖动节点或平移画布时面板跟着走。宫格切分放在「图片工具」菜单的「拆分与标记」里，提供 4/9/16/25 预设和 5×5 自定义点选；自定义面板留在菜单内，切分后的子图按网格排开。框选多张图后拖动，虚线选框跟随被选节点。

## 系统渠道排序与前台别名

系统渠道模型选择器直接读取渠道下的模型列表：一级跨渠道按“模型展示名”分组并显示原色 Logo，二级显示该模型的“渠道展示名”及规格售价；留空使用所属渠道名称。模型调用标识不必相同，也不反查逻辑模型。系统渠道的“前台名称”已移除。调用保留用户选中的具体渠道，收起后显示“模型 · 渠道”，不因另一渠道更便宜而自动切换。图标优先使用图标库的原色版本，缺少彩色版本时使用单色版本；缺少配置时显示通用图标，不猜测产品品牌。

渠道模型价格档支持管理员单独配置积分成本价；后台请求记录同时显示销售金额和成本金额。成本按下单快照计算，不追随之后改价；普通用户页面及接口不返回成本字段。

系统渠道模型列表按规格显示成本价 / 销售价及利润率；文本输入、输出、缓存 Token 分开呈现。勾选多个模型可统一调价：弹窗一行一个模型，展示模型名、渠道展示名（上游 ID）、规格、成本与可编辑售价，多规格在模型行内纵向对齐。输入目标利润率并选择保留 0–6 位小数（默认 2 位），按 `成本 / (1 − 利润率)` 四舍五入实时计算；也可点击「重新计算」覆盖手动值，再逐项修改。保存最终输入售价，服务端校验价格与版本并原子保存，不改变成本或启停状态。

后台系统渠道通过“设置排序”、模型管理通过“自定义排序”打开完整列表。支持搜索选择条目后输入目标位置，也可拖动、上移和下移；列表显示从 1 开始的位置，点击“保存排序”统一生效，取消不会修改线上顺序。渠道行的“更多”菜单支持复制渠道，复制会生成独立的渠道、模型和价格档，并保留原连接配置与凭证。排序不受筛选及分页影响；并发修改会提示重新加载，避免覆盖其他管理员的调整。系统渠道模式下，用户端模型选择器沿用同一渠道及模型顺序。模型排序独立保存，不改变价格、能力版本或启用状态。

系统渠道可设置可选的前台别名；为空时显示渠道名，设置后公开目录和用户会话只返回别名，后台仍保留原名。别名最长 80 字，支持后台搜索。前台模型目录模式保留其独立配置。

注册默认每 IP 每小时允许 30 次注册请求、60 次验证码请求，单邮箱每小时另限 10 次且发送后间隔 60 秒。失败尝试也占请求额度，达到上限后的拒绝不会继续增加计数或延长窗口；限流响应携带真实剩余等待时间，注册页面显示倒计时并防止重复提交。已保存的运行策略仍需管理员按实际共用网络规模调整，不随默认值升级自动覆盖。

定时闲置资源清理与后台手动删除共同保护外观配置引用的浅色 Logo、深色 Logo、登录视频及封面；即使资源超过闲置期限也不会删除，外观配置无法读取时停止相关清理。

## 章节资产提取与任务浏览

画布视频支持鼠标悬停 350ms 后静音预览前 3 秒，不循环；全局仅一个悬停解码器，离开或操作画布立即停止并恢复封面。手动播放优先，系统开启减弱动态效果时不自动预览。

剧情章节支持一次提取角色、场景与道具，分别写入角色、环境和道具待确认资产。输出必须包含三类数组；无人章节可以只产生场景或道具，不把缺失字段当作提取成功。

场景和道具确认后保留描述与生图提示词，尚未出图时显示「待生成图片」。可使用项目画风生成参考图，或绑定素材库中已有图片；提取和确认不会自动发起收费生图。图片绑定创建新资产版本，已有镜头、画布继续引用原图片。生成任务的成功状态与图片绑定共同提交，取消或失去租约的任务不能换图；晚到图片不覆盖较新资产版本，原生成结果仍可在任务中心恢复使用。

任务详情只读取任务与日志，不因打开详情写入画布。视频任务列表和网格优先展示已有封面；没有封面时，在进入视口后提取首帧缩略图。后台请求明细默认仅显示请求，可切换仅下载或全部明细，导出沿用当前筛选条件。

## AI 提示词优化器

提示词优化器是一个内置 AI 能力插件，用于把模糊的生图或生视频想法整理成可以直接使用的提示词。它复用宿主已经配置的文本模型和渠道，不在浏览器中保存或拼接第三方密钥。

### 使用入口

- 创作页 `/create` 的提示词输入框中，点击“优化”。
- 画布中的图片或视频节点提示词编辑器中，点击“优化”。

面板使用紧凑的聊天式交互，跟随当前输入框定位，支持拖动、边缘调整尺寸和窗口尺寸变化。打开与关闭不使用延迟动效，避免遮挡画布或让用户误以为请求卡住。

### 优化方式

| 方式 | 用途 |
| --- | --- |
| 扩展想法 | 从模糊想法补齐主体、场景、构图、光线、镜头等可执行细节。 |
| 精修已有提示词 | 尽量保留原意，只修正表达并补充必要细节。 |
| 强化风格 | 保留主体和动作，强化色彩、材质、光影与指定风格。 |
| 适配模型 | 按当前生成模型和协议调整提示词结构，避免使用未确认的参数语法。 |
| 结合参考 | 使用已连接的图片或文本补充外观、一致性、构图和关联关系。 |

面板底部可以单独选择优化所使用的文本模型；目标生成模型仍取当前图片或视频生成配置。两者职责不同：前者负责整理提示词，后者负责最终生成内容。

### 结果与安全边界

- 优化结果以结构化内容返回，包含正向提示词、规避项、修改说明、假设和可选备选版本。
- 结果可以继续编辑；只有点击“采用”才会回填当前输入框，并自动关闭面板。
- 请求支持流式反馈、取消和错误提示，不会在优化失败时覆盖原提示词。
- 参考素材只提交当前已连接且符合类型的内容；插件不自行访问素材库或后端密钥。

### 相关实现

- `web/src/lib/plugins/builtin/prompt-optimizer.ts`：插件清单、优化方式和模型适配策略。
- `web/src/components/canvas/canvas-prompt-optimizer-drawer.tsx`：聊天面板、拖动缩放和结果采用交互。
- `web/src/services/plugin-host.ts`：将插件文本请求接入宿主现有模型渠道。

## 画布同步与离线恢复

画布编辑会先写入浏览器本地持久化，再由统一同步队列提交 operations。浏览器在线时自动保存；断网、响应丢失或服务端暂时不可用时，未确认请求会保留在本地 journal，恢复连接后按原 `mutationId` 和原操作内容自动重放。同步状态会区分保存中、已完成、待处理和错误，用户无需选择本地版或云端版，也无需手动强制覆盖。

媒体素材先完成资源归属和就绪校验，再提交引用画布的 operations。服务端返回并发或资源冲突时，本地修改继续保留，系统等待下一次基线校验；删除后的迟到更新会被拒绝，不会凭空创建节点。相关同步细节见 [画布 operations 同步](/docs/backend/canvas-operations-sync)。

### 相关实现

- `web/src/stores/canvas/use-canvas-store.ts`：本地画布持久化与 journal。
- `web/src/services/user-data-sync.ts`：operations diff、自动保存、回执重放和远端删除保护。
- `web/src/services/canvas-asset-repair.ts`：提交前媒体引用与素材记录校验。
- `web/src/pages/canvas/canvas-sync-status.tsx`：同步状态显示。

## 画布外观

底部工具栏的“画布外观”面板支持浅色、深色、自定义三种主题，以及点阵、线稿、空白三种网格。浅色画布使用比白色节点更沉的中性雾灰背景，深色画布使用比原深色节点更亮的中性灰背景，让画布底层与内容表面保持稳定区分，同时避免蓝灰背景与黑色工具浮层产生色温割裂。

自定义主题会继承用户进入前的浅色或深色基础界面，并允许在“浅色界面”和“深色界面”之间切换。界面样式复用原项目整套节点、工具浮层、文字、边框和交互状态，不开放这些元素的任意改色；切换界面样式不会覆盖已经选择的画布背景和网格颜色。

自定义主题还允许调整画布背景色、背景明亮度、网格颜色和网格强度。颜色输入支持三位或六位 HEX，可带或不带 `#`；形成合法色码后实时写入当前画布，编辑过程中不会被父级状态覆盖，关闭外观面板也不会撤销。选择新的画布背景色时明亮度自动归零，确保画布首先精确显示输入色；之后仍可沿 OKLCH 亮度轴单独调整。不提供背景透明度，避免画布底色与底层颜色混合后产生偏色。“网格强度”使用 `0%` 最淡、`100%` 最明显的方向，避免“透明度”命名歧义。

自定义外观可以应用到当前画布，也可以保存为当前浏览器、当前账号 scope 下的新建画布默认值。当前画布外观沿用画布项目的既有持久化和同步流程；浏览器默认值不跨设备同步。

## 剪辑成片（时间线编辑器）

“剪辑成片”是项目详情里的时间线编辑器入口（`/projects/:id/editor`），用于把已就绪的分镜视频编排成一段可播放、可导出的成片。它运行在浏览器本地时间线模型之上，通过后端任务队列完成语音转写与成片导出，编辑器本身不直接触碰原始媒体大文件。

### 使用入口

- 项目详情“制作流程 → 剪辑成片”步骤卡，或地址栏直接访问 `/projects/:id/editor`。
- 编辑器按项目隔离时间线状态；离开后再次进入会恢复该项目的编辑器快照。

### 当前能力

- **轨道与命令**：时间线支持添加、删除、拆分、移动、修剪片段等操作，全部通过统一命令状态机执行并进入 200 层历史记录，可撤销与重做；非法操作整批拒绝，不产生半应用状态。
- **预设面板**：左侧“添加”分类提供 8 个内置片段/字幕插件，按分类分组接入同一插槽注册链，第三方插件可与内置面板共存。
- **权限与执行边界**：命令执行遵循失败关闭（fail-closed）策略，`timeline.command` 权限与全局 `plugins.run` 权限分开控制；未授权插件或命令不会被执行或回显。
- **语音转写（字幕）**：对时间线音视频发起转写任务，转写进度沿任务 SSE 回流，完成后生成字幕轨。
- **成片导出（渲染）**：发起渲染任务，由服务端 ffmpeg 按渲染计划输出成片；渲染成功后在项目概览的“剪辑成片”步骤卡呈现“已输出 N 个成片”，并作为该步骤完成度的判定依据。
- **AI 编辑助手**：可以用自然语言描述剪辑意图，系统将其解析为受支持的命令序列；不超过 3 条命令时直接执行，多于 3 条先给出差异预览，确认后才批量执行。

### 运行环境要求

- 语音转写依赖本地 whisper.cpp 服务（`CANVAS_WHISPER_BASE_URL`），未配置时转写任务明确失败。
- 成片导出依赖服务端 ffmpeg（`CANVAS_FFMPEG_PATH`，留空时在 PATH 中查找）。
- AI 编辑助手需要可用的文本模型渠道。

## 创作首页纵深画廊与灵感库

创作页空态是直线纵深图片画廊：11 张横版卡片沿 Z 轴前后排队，当前一张在最前、最大，其余依次后退缩小并左右对称。滚轮、两侧按钮和自动轮播都能切换，切换只动 `transform` 与 `opacity`。卡片带玻璃描边、圆角和投影，底部是「行动点 / 标题 / 描述」三段信息，只有最前那张露出。队列跟随输入框的创作类型：选图片只排图片灵感，选视频只排视频灵感，选文本用本项目原创条目。每次进场和每次换类型都重新随机抽一批，并记住最近出现过哪些，走完一轮自动换批。

## 画布外观预设

顶部保留浅色、深色和自定义三个入口。浅深切换恢复该色调最近的预设或微调；自定义仅展开、收起当前色调的设置，切换浅深不会改变展开状态。浅色提供经典浅灰、粉色、米色、浅绿，深色提供经典深色和柔和深灰；可调整明亮度、网格强度，并在“更多颜色”中修改背景和网格颜色。

单个画布自动保存预设快照、浅深色各自的微调和网格样式，工作台主题切换不覆盖已有画布。未设置新画布默认时，新建画布随工作台明暗选择经典预设，并默认使用线网格；旧画布缺省仍按点网格处理，已有显式颜色和参数继续读取。“设为新画布默认”仅作用于当前账号与本浏览器。外观及添加节点面板限制高度并允许内部滚动。
