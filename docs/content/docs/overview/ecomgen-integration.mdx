# EcomGen 与电商画布接入方案

本方案依据 [linbei0/EcomGen](https://github.com/linbei0/EcomGen/tree/f8e6e7b52c1ff74a614052728ccb24c2b4c5e7b6) 的固定版本进行源码分析。已经把套图模板协议、视觉规范、参考套图分析、结果选择和原图包导出接入影策现有流程；没有运行第二套 EcomGen 服务，也没有改动用户模型配置。

当前主入口为独立「电商生图台」：商品卡片点击后自动连接当前商品，重复进入定位已有节点；也可从工具栏和添加菜单创建。规划、手动编辑方案与逐张/整组出图不依赖创作表，创作表保留可选。

## 当前实现与边界

生图台直接显示智能规划、套图工坊、模特选角、花型工坊、Listing、印刷规格包、成包流水线和分层交付入口，点击后进入对应操作。分析可选已加入的 Skills，加载正文与关联文本并记录来源；这是文本任务的上下文注入，不代表提供上游联网研究等 Agent 工具。默认指令全文仅通过管理员接口预览和编辑。

| 能力 | 当前状态与入口 |
| --- | --- |
| 模板创建、导入、检索、发布 | 后台电商画布的套图模板页签；支持单套 suite v1 JSON，导入默认草稿，审核启用后发布 |
| 模板视觉规范与快照 | 创作表补充信息中选用模板；确认替换行，视觉规范进入分析，已使用的快照不受后台修改影响 |
| 商品事实、禁止项、市场与语言 | 商品档案与创作表补充信息进入分析；参考模板不升级为商品事实 |
| 参考套图分析 | 将参考图连接到商品节点的视觉参考槽，创作表选择看图模型后使用参考套图分析；提取顺序与视觉方向，不复制参考商品参数 |
| 候选结果采用与导出 | 每行选择成功版本，默认最近成功结果；导出该选择的原图和 manifest v2，区分规划与真实任务记录。显式选择被移除时不自动换图；可按采用版本重新装订长图 |
| 私人模板沉淀 | 当前表标题、职责、视觉规范可保存为当前账号的浏览器模板，跨画布复用；没有云同步 |
| 专业电商流程 | 添加节点与连线菜单开放商品信息、画面制作、参考分析、修改交付四组；复用既有排版、信息图、A+、视频、改稿与交付实现 |
| 异步任务、模型、计费、资产、蒙版与拆图 | 复用影策原有能力；不复制上游无鉴权 API、不增加第二份 Provider 配置 |
| 1173 套内置目录 | 已内置固定版本完整 JSON，保留 MIT 许可；后台、生图台、工作台规划和创作表可搜索、预览完整视觉规范与逐张参考提示词。后台可载入为停用草稿，编辑并保存发布 |
| 25 图型原文 | 已提供图型选项，未复制 ecom-skill 的上游原文；该包记录了额外来源许可边界 |
| 默认分析指令 | 嵌入上游 planner.ts 原指令及 MIT 许可；智能规划与旧四用途各自适配输出格式，后台空覆盖即使用默认 |
| 独立生图台 | AI 规划或手动添加画面，编辑整套视觉规范与逐张完整提示词，直接生成连接的图片结果；检查输入、方案、账号与项目变化，支持停止 |
| 模特选角生成、Suite Forge 模板沉淀 | 更多电商功能中已提供多姿态逐张生成、参考套图反推和私人模板保存；真实模型效果及私人库云同步未验收 |
| POD 花型、确定性改色、验缝、300DPI 规格包、Listing 与成包流水线 | 已增加 AI 花型操作、像素改色/验缝、物理尺寸 PNG ZIP、文案和顺序流水线实现；真实素材端到端及中断后持久恢复仍待验收 |
| 分层 PNG/PSD ZIP | 已提供 AI 分层入口和真实图层导出实现；PSD 尚未独立解析和编辑器验收，不视为交付验收完成 |
| 平台画面参考 | 按固定上游版本整理淘宝/天猫、京东、拼多多、抖音、Amazon、Shopify 六类规则，进入规划、反推和 Listing 上下文；自定义未知平台不套用其他平台规则 |
| 生图台候选采用与交付 | 每张画面可明确采用成功版本或自动选最新版本，ZIP 导出所选原图与任务清单；方案、需求、商品实拍或输入连线变化阻止旧结果交付 |
| 模板再次选用与后台编辑 | 生图台/工作台可选择后台公开模板和当前账号浏览器私人模板；保存包含画面职责与参考提示词，超出保存上限明确报错。后台按能力导航编辑单项指令 |

分析指令仅管理员维护，公共配置省略该字段，worker 在内存中注入。日志隐藏该类请求/响应正文；模型输出仍须验证，不能承诺模型绝不复述系统文本。自动装订只接受本轮成功且已落盘的图片，等待、失败、取消和未应用的新结果均阻止装订；上传前复查计划、图片和任务身份。逐行采用选择用于预览、ZIP 导出和主动重新装订；既有长图保留。切片规格独立选择，超大合成尺寸、不安全切点和不合格片高阻止交付。

## 建议的接入方式

规划接入「商品 → 电商生图台 → 图片结果」，原「商品 → 创作表 → 结果」流程保留。继续使用影策的登录、模型配置、任务队列、资源存储和计费。完整部署第二套 API、Redis Worker、SQLite 与 Provider 管理会带来双份任务和配置，当前没有必要。

上游默认规划指令保留商品事实边界、画面职责、统一视觉锁和完整生图提示词规则。用户选中的内置模板全文直接进入规划上下文；没有暴露上游 Agent 的模板工具或联网研究工具，服务端适配禁止假装调用这些工具，并按现有 schema 输出。套图反推与 Listing 使用影策适配指令，未声称逐字复用上游技能全文。联网视觉研究、像素保护、POD 实物示意、人工审核阻断与持久流水线恢复仍有缺口。

本轮操作检查修复了采用方案时原生图台向新生图台的非法连接，以及下游结果回连造成的环。成功状态在结果落盘或文本解析校验后更新；流水线全部完成后清理各步骤的执行中状态。生图台执行记录保存当前一次操作，不是可持久恢复的多轮历史。旧结果没有完整来源快照时不能冒充已核实的当前商品结果导出，图片节点仍保留供人工核对。

| EcomGen 能力 | 上游入口 | 画布中的对应位置 | 接入方式 |
| --- | --- | --- | --- |
| 类目套图与图型规范 | `packages/ecom-suite/src/suite-catalog.ts`、`packages/ecom-skill/src/catalog.ts` | 创作表的用途、标题、职责和分析指令 | 后台发布模板；用户选择后生成可编辑的行，最终提示词由分析模型结合商品实拍生成 |
| 商品事实与声明约束 | `packages/agent/src/planner.ts`、`apps/worker/src/job-plan.ts` | 商品节点已有 `productProfile` 与参考图 | 明确商品事实、参考风格和禁止声明；模板和联网研究不得升级为商品事实 |
| Campaign Style Lock | `packages/ecom-suite/src/suite-catalog.ts`、`packages/agent/src/planner.ts` | 当前用途创作表的整组视觉方向 | 分析时统一色板、布光、字体及背景；逐行确认完整提示词，执行时不重复拼模板 |
| 套图反推 | `packages/agent/src/suite-forge.ts`、`apps/worker/src/job-suite-forge.ts` | 参考图片组接入创作表 | 提取视觉方向和行顺序，人工审核后存成私人模板；后台审核后才可发布公共模板 |
| 多候选与审核 | `apps/api/src/routes/storyboard.ts`、`apps/worker/src/job-generation.ts` | 表行对应的图片版本 | 使用现有结果节点和运行 ID，支持采用某一版；不重新建立第二套生成任务 |
| 分层与导出 | `apps/worker/src/job-layers.ts`、`job-export.ts` | 生图台更多电商功能、图片节点及交付节点 | 复用 AI 分层，新增 PNG/PSD ZIP 实现；独立解析、编辑器和大图验收待完成 |

当前版本实数：`packages/ecom-skill/src/templates/` 有 25 个模板文件，`packages/ecom-suite/src/suites/` 有 1173 个 JSON 文件。1173 套原文件已压缩嵌入后端，按页返回摘要、按套读取正文，不塞入管理员配置。可用 `scripts/import-ecomgen-catalog.py` 从固定版本干净源码重建；所有转换后模板通过现有保存校验。文件数量不代表每套都已验证适合当前商品或平台。

## 第一阶段：类目模板进入创作表

1. 后台在现有电商配置中增加「套图模板」管理。每套记录用途、类目、版本、行标题/职责、视觉方向、启停与来源；已使用的表保存模板版本快照。
2. 在创作表内选择模板。新表可直接填入标题和职责；已有编辑须展示替换影响，不能静默覆盖用户提示词。
3. 分析商品时读取实拍、商品事实、模板和用户指令，输出每行可直接生成的完整提示词。继续使用当前分析模型、Skills 和生图模型选择。
4. 用户确认后走现有批量队列，结果保留商品、表、行和运行归属；模型失败或解析失败必须可见，不以模板占位词伪装成功。

本阶段代码已实施。专项回归覆盖模板解析、发布过滤、编辑保护和快照保留。后台已验证真实保存与刷新持久化；真实模型的商品分析、风格一致性和逐行出图仍需验收。

## 第二阶段：参考套图反推与候选采用

创作表参考套图通过商品节点的视觉参考槽进入分析，结果写入创作表，分析前后检查表格、商品事实和参考图快照。每行可选采用版本并用于 ZIP 导出和主动重新装订，失败重试由用户明确触发。生图台侧栏可独立反推整套视觉规范与逐张方案，采用为生图台或保存私人浏览器模板；私人模板云同步与上游完整结构字段尚未实现。

## 若必须复用 EcomGen 完整服务

上游 `apps/api/src/app.ts` 明确没有认证层；CORS 不是账号鉴权。只能放在私网，由影策后端提供受控适配器：

- 在影策内校验账号、画布和资源归属，维护账号/画布/表与 EcomGen project/job 的映射，禁止透传任意项目 ID。
- 后端将受控商品快照上传到 EcomGen，调用 `POST /api/v1/projects/:projectId/planning-jobs`，读取 storyboard，将 `promptInstruction` 映射为表行 prompt。
- SSE 只通知刷新；通过 REST 查询最终状态。取消、超时、重试和幂等分别落实到持久任务。
- 生图继续走影策，避免双重排队、额度和模型配置分叉；若改为 EcomGen 生图，需要另外完成凭据隔离、计费对账和结果回传。
- 两套数据库独立保存，资源通过受控上传/下载传递，不共享可写数据库文件。
- 新服务镜像仅通过 GitHub Actions 构建；本机和服务器只拉取运行。
