# 室内设计参考视频分析与实现对照

参考素材是一段约 140.13 秒、960 × 544、带中文解说和字幕的家装工具介绍。分析使用每秒抽帧、整段画面检查与本地字幕 OCR 交叉核对。OCR 有少量错字，以下按画面与前后文整理；没有独立语音转写，也没有拿到视频中的原始 CAD 或可运行工具源码。视频中的推广、评论、点赞和“领取技能资料”只属于素材内容。

## 视频实际讲了什么

| 时间 | 可确认的内容 | 产品含义 |
| --- | --- | --- |
| 00–12 秒 | 给 AI 一张户型图，生成装修设计网页；展示鸟瞰与室内视角 | 输入应围绕用户已有图纸，输出要能动手调整，不能只给效果图 |
| 13–27 秒 | 声称使用 108 ㎡、三室两卫案例；读取墙体、门窗和尺寸，还原成设计数据 | 结构、尺寸和开向必须是可核对的数据。画面中的 240 mm 墙厚、900 mm 门宽、1500 mm 窗高是演示数字，不是所有项目的默认实测值 |
| 28–37 秒 | 左侧 2D 平面、右侧 3D 鸟瞰；切到第一人称检查比例和家具摆放 | 两种视图要共用位置；漫游用于观察真实尺度和通行空间 |
| 38–51 秒 | 家具拖动、替换、旋转；强电、照明、网线、给水、排水；厨房独立回路、强弱电避让、带坡度接立管 | 家具要独立可编辑；专业点位不能混在一张无语义图里。自动工程设计需要现场及专业数据 |
| 52–62 秒 | 吊顶、灯带、铺装、拆改、定制；绘制轮廓后拉伸或旋转成家具 | 需要可操作的几何工具，不能只有一句话“支持定制” |
| 63–70 秒 | 自动算量、报价，输出平面、顶面、水电、铺装及 CAD/DXF | 工程量、图纸和模型必须共用数据。视频中的预算数字是例子，无法据此验证当地报价 |
| 71–77 秒 | 办公、培训、商业空间；从装修公司 CAD 布置图还原 | 不能把所有输入强行当住宅，也不能臆造院子、屋顶或公共空间 |
| 78–92 秒 | 面向买房业主、准备装修的人和房产/家装内容创作者 | 业主用空间与预算，设计师用尺寸与交付，内容创作者用视角和模型素材 |
| 93–110 秒 | 四步：图纸、需求、确认细节、生成网页；可原样还原或补家具；确认层高、公共区域 | 读图结果必须有确认节点。首次识别不能直接冒充“一比一准确” |
| 111–128 秒 | 自称设计方案和施工图辅助工具；承重、结构和实际水电以实测、物业结构图、专业复核为准 | 保留专业边界。可编辑 DXF 不等于通过施工审图，自动生成路线不等于工程合规 |
| 129–139 秒 | 总结“一张图，一个家”，推广资料与互动 | 不转化成应用操作或外部发布要求 |

空间表现偏向浅色墙面、木质/暖色家具、干净鸟瞰视角和开放室内视野。可见的户型组织包括客餐公共区、卧室、卫浴与厨房；视频压缩画面不足以可靠抄录全部房间尺寸。因此本轮没有捏造视频案例的完整坐标，也不宣称复现了那套 108 ㎡户型。

## 与已有代码的差距

已有能力包括图片出装修效果图、两阶段读图/装修、结构与尺寸链校核、同图结构基准复用、three.js 查看器、门窗/家具自动几何、局部编辑和新版本保存、GLB/JSON 交付、石材排板。主要差距是没有真正的平面联动编辑、第一人称行走、明确的专业图层、整套方案算量、实际 DXF，以及首次读图后的人工确认。

目标职责明确如下：`scene-compile.ts` 提供唯一的实际墙、洞口和家具定位；`design-plan.ts` 提供辅助图层校验、平面图元、算量、SVG/DXF/离线交付；页面只负责交互与项目保存；`scene-walk.ts` 负责纯碰撞规则；后端 `interior/design.go` 校验持久化的辅助图层与报价。辅助图层不修改结构基准。

## 本轮落实

1. **读图确认**：首次图纸分析成功进入 `review`，刷新后仍保留待核对状态，不自动提交下一次收费建模。原图与结构预览并排，多层图纸可逐层切换；确认层高、空间、门窗与尺寸后，再选择保留原图布置或补家具。保留模式在最终保存与流式预览里都强制保留原家具。
2. **2D/3D 联动**：增加 2D、3D、并排视图。平面门窗与家具使用编译器的实际坐标，平面、三维剖切、漫游与调整目标共用当前楼层。点房间/家具联动已有调整面板；拖动已写入方案的家具，松开后检查空间碰撞并保存新版本。自动生成但未写入方案的家具保留只读显示，可通过既有对话流程先写入方案。小屏上下排列并保留每个视图的可用高度；联动视图默认收起三维密集标注。
3. **第一人称**：W/A/S/D、方向键移动，拖动环顾，可选择楼层与房间。只在当前层室内行走，墙体保持完整；实际门洞可通行，墙、柱子、楼梯洞、家具与定制造型会阻挡。键盘只在画面聚焦时接管。当前不做楼梯攀爬与跨楼层连续导航。
4. **专业图层和造型**：布置、地面、顶面、强电、照明/灯带、网线、给水、排水、定制与拆改分开。可绘制点位、路线、封闭轮廓，填写名称、离地高度与拉伸厚度。顶面/定制/铺装轮廓进入三维预览；轮廓拒绝自交和非法尺寸。拆改只做标记，不会删墙。当前是人工辅助规划，没有宣称完成自动负荷、管径、坡度与强弱电避让计算，也没有新增无依据的暖通功能。
5. **整套算量报价**：地面扣墙体/柱子/楼梯洞；顶面按净投影；墙面按外墙单面、隔墙双面扣门窗；家具按实际编译结果，管线按手工路径长度，定制轮廓按投影面积。材料按损耗增加采购量，人工按净量。单价未填为待报价，已知零单价可明确录入。未齐报价仅展示已报价小计，不判断是否超预算。几何尺寸和材质取量仍须复测。
6. **实际交付**：同一份图元生成 SVG 与毫米 DXF，图层、门窗、家具、尺寸可编辑；方案包包含工程量报价 CSV、辅助图层 JSON、原场景、房间与家具清单、离线网页。离线网页可双击查看各层平面/辅助图层和报价，无 CDN 或外部脚本。完整三维与漫游仍在应用里，三维资源另导出 GLB；没有把平面离线页称作完整离线三维工具。

## 证据与验收

专项覆盖：平面/三维定位一致、真实门洞通行、墙体与家具碰撞、防低帧率穿墙、几何取量与报价、空报价/零报价区别、非法标记/自交轮廓拦截、XML 文本转义、DXF 单位和实体、离线网页自包含、项目三方合并。前端 10 个专项文件共 63 项测试通过；其中真实 Studio 的隔离 DOM 验证包含首次分析转核对、确认后提交、保留家具、多层预览和楼层联动 5 项流程。图形渲染模块在 DOM 测试中替身隔离，WebGL 另用真实浏览器查看。前端 `bun run build`（包含 TypeScript）与后端 `go test ./internal/interior` 通过。

真实页面验证已有模型的平面、联动和室内漫游，并从页面下载方案包。平面键盘选择会客厅可同步漫游房间与调整目标；漫游下拉选择餐厅也同步调整面板。1440 × 900 桌面联动与 390 × 844 深色窄屏无横向溢出；窄屏可滚动进入三维视图，每个视图保留 360 px 最小高度。窄画布按宽高比调整取景，重置后可完整看到户型。强电图层的路线工具、名称和高度输入可用，未绘制时不能完成路线。包内 15 个文件包含 3 份 DXF 与自包含离线平面网页。使用独立 `ezdxf` 读取与审计：DXF 实体数分别为 751、729、729，单位为毫米，三份均为 0 个错误、0 项自动修复，中文 UTF-8 文本可读取。家具拖动写入未在现有用户方案上执行，位置校核和局部版本生成由专项测试覆盖。

此工作副本的 `docs/` 没有文档站 `package.json` 或编译配置，因此没有宣称文档站构建通过。

本轮不触发收费生成，不改用户现有方案，不发布、不部署。真实模型的视觉读图准确率、复杂公共区和商业 CAD 的识别质量、桌面 CAD 软件的字体/打印表现、施工工程合规仍需实际素材和专业验收。完整离线三维编辑、轮廓旋转成旋转体、结构级墙厚读数、自动 MEP 路由属于后续独立工作，不能用“已经支持”掩盖这些差距。
