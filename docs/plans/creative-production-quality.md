# 三大工作台：商业成品质量与专业流程改造

## 判断与本次交付

原有功能能发起生成，但成品控制不足：生图把排版和文字准确性全交给模型；室内缺少可计算的材料方案；视频改写集中在口播，原商品的画面描述容易残留。单纯增加“高级、精美、商业摄影”等形容词无法解决这些问题。

本次沿三条实际流程开发：生图拆开摄影底图与程序排字；室内增加材料、排板和预算；视频把平台、叙事、动作与首帧写入逐镜方案，并接到画布生成和直接出片。旧结果保留，错误明确显示，写入与生成验证同一份合同。

商业审美尚需真实商品与真实模型评测。本次模拟 API 只证明页面、保存、排字和导出流程，不证明转化率、现场工程精度或生成一致性。

## 生图台

### 已开发

- 表单可选“模型整体设计”或“程序排版”。选择存进生成记录，历史导出沿用当时策略。
- 策划按平台制定首屏利益点、购买问题、证据与摄影节奏；白底主图继续禁止促销字与道具。
- 程序排版使用与底图生成相同的百分比文字区，避免留白在上、导出文字却在下的错位。
- 栏目、标题、副标题与说明分别排字。参数屏双列；数据、要点与收尾屏按编号和分隔线组织。
- 大图预览与单张、整套下载使用同一排字链路。字体加载后测量，超出区域明确失败。
- 排字以 PNG Blob 编码并释放临时引用；修复内嵌浏览器无法下载排字 data URL 的路径，实际下载文件已核对尺寸与文字像素。
- “仅更新排字”保存文案并更新成品预览，不重新调用生图模型。只有真正的出图调整才提交图片任务。
- 调整面板指出普通口号、重复标题、绝对承诺与信息过密；只从已确认/可见卖点提供替换候选。

### 待完善与方案

1. **真实样本评测**：每个平台选择有授权的商品，按食品、美妆、数码、服饰覆盖品类；同素材比较现有模式与程序排版，记录商品外观、文字正确性、缩略图可读性、模块节奏和人工通过率。没有样本前不能宣称达到商业平台水平。
2. **视觉选择与重拍**：先比较几份不同构图，再由用户选方向；生成后审核商品形体、遮挡、信息区与事实。重拍必须展示具体问题和新增费用，不能后台无上限重试。
3. **字图编辑**：将目前程序排字升级为可编辑标题、色块和参数图层，先支持坐标/字号/颜色与逐屏导出。摄影与文案继续分离，避免每次改字重生整张图片。
4. **参考解析**：用户上传有权使用的参考图，抽取色彩、焦点、留白与模块关系；禁止复制竞品品牌、商品与未经证实功效。设计方向保存为快照，避免后台模板更新改变旧作品。

当前程序排字逐字使用已有文案，不自动翻译。没有做 OCR、商品分割或视觉审美自动评分；简单文案提示不是平台合规认证。

## 室内装修与石材

### 已开发

- 新“装修 / 石材”工作台，支持整体、墙面、地面、台面；软装焕新、旧房改造、毛坯；大理石、岩板、石英石、瓷砖、木材；表面工艺与灯光独立。
- 输入毫米尺寸、板幅、拼缝与预留损耗；直铺、左右/四向对纹、错缝计算分块与边缘裁切，限制超大分块数。
- 上传整块实板照片，预览各块裁切与镜像。资源以标准 `texture.resourceId` 引用，受资源归属与引用保护。
- 净铺面积、含用户预留损耗面积、材料与铺装金额、区域预算同步计算。未知报价返回 null，不伪造零费用。
- 导出可独立打开的 SVG、逐块 CSV、JSON 方案和复核说明；有实板时打包照片并使用相对引用。
- 专业方案随项目及生成轮次保存，双窗口独立修改合并。服务端校验当前与历史方案参数和实板归属。
- “按材料方案出效果图”回填效果图设置；报价与正式出图读取同一专业方案与实板参考。

### 待完善与方案

1. **区域定位**：在真实空间图上标注墙/地/台面 mask；用位置约束限定替换，保存比例基准和保留区。以门窗、透视和其他区域未被改动作为验收条件。
2. **实板与加工**：支持多板照片、批次、板号、每块来源、裁切起点、方向、开孔与锯缝；增加连纹拼验、加工顺序和装箱清单。先做人工确认流程，避免用合成纹理冒充供应商板材。
3. **装修工程量**：分别维护地面、墙面、顶面、门窗扣减、基层与收口工程量。材料费用、人工、运输、税费分项；每项单价由用户或可验证报价提供。
4. **空间方案**：深化现有可编辑空间，加入尺寸约束、门窗、家具轮廓、通行与碰撞检查，再接照明与多视角效果图。CAD/施工图应有独立专业审核出口。

当前排板不是工厂最优开料；含损耗面积不是整板采购量。没有计算台面开孔、悬挑结构、现场厚度或防水节点。镜像不能证明连号实板对纹；效果图不能保证毫米几何精度。

## 视频复刻

### 已开发

- 平台、购买/教育/品牌目标、表现方式与全片连续性保存为导演策略。
- 逐镜定义钩子、问题、演示、证明或行动，配合景别、运镜、动作始末、声音意图与剪辑衔接。
- 画布改写任务返回新商品的首帧、视频动作和导演方案；选用版本同时替换旧画面描述，生成使用这些字段。
- 缺动作、缺首帧/视频提示词、无证据证明、超长描述或超时长口播的导演响应被拒绝，不通过截断掩盖模型失败。
- 手改导演的动作和证明依据也在建立生成画布前检查，未完成方案仍可作为草稿保存。
- 直接出片的重新拍镜头接入同一导演设置。换元素保留原片动作和机位，只使用连续性约束。
- 导演输入变化后待重生成，同时保留旧候选；费用预估包括待重拍单元。未确认结束的原任务不能被丢弃或重复提交。
- 导演内容指纹固定长度，避免每个单元重复保存配方而撑大作品；刷新可读回。服务端对两种入口验证枚举和长度。

### 待完善与方案

1. **镜头连续性评测**：记录人物、商品、光线、姿态的跨镜差异；用有授权原片和明确商品资料测试，不只检查任务成功。
2. **首尾帧与角色卡**：按模型真实能力传递首尾帧、人物/商品参考；能力不支持时明确提示。不能只在 prompt 写首尾帧却声称功能已接通。
3. **声音和剪辑**：深化已有配音/字幕/音乐链路，加入口播时长检测、音乐降音、声音卡和断句；验证字幕时间码、口型与拼接动作。
4. **导演自动策划**：直接出片目前可手动编辑导演方案，自动导演策划在画布流程。后续复用严格解析的策划服务到直接出片，保存多版本，逐镜选择并展示费用。

每秒字符预算只估计承载量，不保证模型语速。声音意图与剪辑衔接只是模型/剪辑建议，尚未把每个选择变成真实音效与转场。真实供应商生成、口型和跨镜一致性未由本轮验证。

## 验证与上线边界

- Web 专项覆盖排字溢出、事实文案、排板、报价、合并保存、导演解析/编译与生成单元恢复。
- Go 专项覆盖专业参数、生成/报价实板引用、保存归属以及导演策略合同。
- 真实路由在隔离模拟 HTTP 下验收了文案修改、排版预览、专业方案与导演保存、刷新读回、预算计算、ZIP 下载和解包。
- 本次没有修改数据表。新增字段进入现有 JSON 文档、任务输入与结果；不需要数据库迁移。旧代码无法编辑新增专业字段，回滚前应导出方案。
- 推送必须经过仓库全量门禁。检查摘要由交付记录给出，不能把此处的验收标准当成已执行结果。
- 没有生产部署、付费模型成绩、平台上架、施工审核或转化实验；缺少 PostgreSQL/Redis 的专属验证由 CI 和部署环境继续执行。
