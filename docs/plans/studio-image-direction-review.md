# 生图台：商品图片设计拆解与本轮实现

## 当前执行合同

新生成统一为「商品分析 → 文案与画面策划 → 图片模型一次生成完整图文」。表单、助手工具和弱文字模型均不再提供或自动选择程序叠字。候选记录实际 `textMode=model`，旧方案重试得到的新成品在预览、下载时也不会再次叠字；历史无字底图保留原交付行为。

策划新增 `designAnalysis`，从实拍颜色、形体、可见材质和买家问题解释色板、背景明度、光线、实际可用视角及字阶；经过解析、持久化、生成组快照后进入图片提示词。详情数量继续由用户所选 2–20 屏决定。取消自动把首屏成品加入后续参考图，避免整套复制首屏的机位与布局；明确选定的用户参考图仍生效。

下文程序排字及自动首屏参考的试验属于历史过程，不是当前生成方式。模型整体图文的中文准确度、形体还原和布局服从仍需查看真实成品，提示词通过不等于设计达标。

真实整体图文试稿：原 DeepSeek 给出四屏和设计依据，原 GPT Image 首屏成功并可取得原图。中文标题与两行注解清楚，商品前框和灰绿镜腿可辨，但仍变成上文下图，并出现策划未要求的植物；这张只证明整体图文链路，不算版式合格。之后补充要求明确解除暖白书桌/窗光方向，模型重新根据透明边缘的明度对比策划石墨、灰绿、冷白方案；未为验证首屏而自动生成整套。

## 流水线效果的根因与修正

原排字固定系统黑体、标题字重和说明比例；参数、数据、卖点与对比容易变成同一列文字。旧方向要求定位、主线照用，用户的新调整因此仍带回草地、风车。服务端 KB20 把配色与规格视为低级文案，并用未经确认的体验替换具体事实。大图和下载有程序排字，结果列表却显示无字底图，让用户看不到最终设计。

本轮修正实际路径：

- **字形与节奏**：本地 Noto Sans SC / Noto Serif SC 可变字库；八种调性定义字重、字号、字距与行距。杂志大标题配约 28% 的小字说明；宋体标题配黑体正文；数据标题更大且更轻。参数分列、对比两栏、卖点横排，窄侧栏自动单列。保留手工分行与值内分隔符，不加虚构页码。
- **文案与依据**：标题回答购买问题，说明给理由，正文给参数或证据。配色可以直接作主题；透明不能推出视力改善，小包装不能推出够用一天。泛口号与整套重复标题进入交付提醒。
- **调整优先级**：本次补充高于旧方向，冲突的场景、调性、道具与色板重做；商品事实保留。模型漏写新主线时不补回旧主线。没有调整时仍尊重用户选定方向。
- **实际呈现**：列表进入视口后生成排版预览；大图、单张下载、整套使用相同字库与调性。修复单张下载漏调性、预览缓存漏构图及助手方案刷新丢字体/墨色风格的问题。
- **知识库**：KB20 文案和版式通过既有版本导入更新，保留管理员手改、驳回和停用规则，不直接覆盖后台内容。

两种字库均采用 SIL Open Font License，许可证随依赖保留。中文可变字体增加约 11 MB 构建资源，按字符分片加载，不向第三方字体网站发送文案。八种调性使用两种真实字库，不等于八套字体或商业书法字库。

## 提示词要写具体条件

“高级、精美、爆款、商业摄影”不足以约束成品。提示应包含商品真值、单屏问题、拍摄机位、光线方向、商品占位、文字留白和信息模块。

例：透明前框与柔灰绿镜腿的分区配色；侧逆光勾出真实可见框边；根据背景明度保持透明边缘可辨，标题“清透前框 柔灰收边”，说明只写已知配色；由图片模型同时完成摄影、字体与信息分区。另一方向使用左图右文、宋体宽字距与克制的小字，保留相同商品事实。只有正面素材时不安排不可见背面和内部。

白底主图不强塞文案，模特图不强塞参数，规格图不强塞情绪口号。多屏变化来自购买问题和摄影结构，而非只轮换颜色。国内购买决策图、Amazon 白底与 A+、小红书内容封面等策略仍是设计建议，最终规则由商家后台核对。

## 真实生成与差距

本次续接重新查看了稿定女包完整详情：约 790×11281 的长图里，首屏摄影拼版、穿搭、产品说明和微距各有职责，字体与边距保持一套，图文重心随内容变化。与本地用户最近十屏的结构图对照，原程序文字“看得清 结 / 构在这里”拆坏短语，引线与拼格还会退化成同一列文字，商品档案误归服装后提示词混入领口、袖长等条件。固定十屏和强制装饰节奏又放大了缺少商品证据的问题。

本轮按实际执行能力修正：详情数量从表单到知识注入、解析和生成统一为所选 2–20 屏；有效屏数不符时停止，不裁剪、不补屏。移除人物、撞色、悬浮和版式数量的硬性凑数，策划过的屏不再追加通用品类构图。未确认材质不参与布光，商品原图只锁身份。程序排版只承诺独立留白区可执行的结构，不能完成的商品引线和拼格提前报错；短语断句与实际底图字色对比已修正。

真实四屏使用原商品、DeepSeek 与 GPT Image。首屏试稿只提交一张，生成记录保留四屏和三个待生成位置；首屏第二候选可读、无旧展台，但仍是上文下图，未严格执行左右分栏，不能算版式完全合格。采用后续生成三屏，第三屏完成局部大裁切加三条结构说明，第四屏完成配色收束和标签；同套首屏作为色调与摄影参考进入提示词，原商品图仍是外观依据。第二屏上游返回 524，后端状态为失败，未再次提交，不能把 3/4 成品说成四屏完成。原失败任务与候选保留。

交付检查实测显示“3/4 张”并明确缺少第二屏。ZIP 下载操作未收到浏览器下载事件，也未定位到下载文件，本次不计为下载成功；既有程序合成与导出测试不能代替完整四屏实际交付。图标、商品小字与局部形体仍须人工对照原图；一套商品只有一张正面实拍和少量可见信息，无法据此证明使用表现、材质、尺寸或售后。

复用原商品、原 DeepSeek 和 GPT Image。第一版返回暖白透光棚拍，旧风车消失，粗黑标题与小字说明由程序绘制；实际下载为 768×768 PNG。第二版采用宋体与右侧字区，但初次镜腿侵入字区，不能算合格；针对折起镜腿和左侧占位重拍一次后，商品与文字分开。旧候选保留，没有静默反复付费。

这些样图证明字体、方向调整、预览和导出可用，不能证明商业审美、转化率或各平台上架标准全部达标。模型仍可能忽视留白，品牌细字与局部结构须与原图核对；768 像素也须按目标平台尺寸检查。未完成商品分割、OCR 或自动遮挡检测，不能用文案提醒冒充视觉审核。

下一阶段：

1. 用有权使用的真实店铺图组补齐淘宝/天猫、抖音、小红书同品类样本，标注主图、卖点、参数、场景和详情模块，记录来源及权限。
2. 服饰、食品、护肤、家居各用真实商品比较多个创意方向，核对形体、品牌字、缩略图阅读、模块节奏及人工通过率。
3. 用局部图像编辑调整模型生成的文字、位置、色彩与裁切；商品边界/保留区独立约束。先做人工标注确认，再评估分割及 OCR，避免只靠提示词保证不遮挡。
4. 建立预览、单张、ZIP 与长图的浏览器回归，覆盖宋体、长参数、多语言、白底禁字及跨窗口保存。平台规则与设计质量分别验收。
