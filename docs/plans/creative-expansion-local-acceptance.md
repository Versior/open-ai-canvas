# 创作扩展的本地验收与后续边界

本轮在既有用户数据的测试副本运行前后端，复用原模型渠道、账号和素材引用。室内局部调整另存场景版本；手动调整不请求模型，对话调整只接受选定对象的严格修改，拒绝越界字段。现有家具布局采用网格和自动贴墙规则，不能作为施工 CAD 或精确碰撞模型。

## 已验收与继续开发

生图策划的账号误判来自局部变量遮蔽，业务范围和账号范围已分开。真实商品策划返回 10 屏；单图调用原 GPT Image 渠道完成，刷新可恢复。账号隔离回归仍拒绝切换账号后的提交。

用量卡真实明细展开与收起能恢复原摘要高度，整卡收起会清掉明细展开偏好。皮肤以角色区插画、消息造型、输入框和用量边框共同呈现；自动皮肤依据角色类型，主色取当前角色代表色，手选皮肤可覆盖。

模型与费用合同集中在既有模型选择、报价和任务账务模块。快速与专业室内模式使用相同的用户选择优先规则；报价和生成共享模型引用。按用户反馈，创作页面仅保留一行预计积分和实际消耗，不展示 Token 单价、预授权说明、冻结与待核对金额或逐任务列表。助手输入区移除额外报价和结算段落；生图底部只保留图片预计积分。缺失账务直接隐藏，不能当作免费；详细账务仍由任务中心提供，实际 usage 会导致补扣或差额退回。未配置积分兑换关系时不显示人民币估值。

后续优先完成三类真实验收：平台解析的有效下载率与限流，换装/换脸的身份和服装细节通过率，多视角室内与石材设计的结构一致性。网络服务失败不能用新增地址数量替代可用性；通用图像编辑与图生视频也不能当成精确整段视频换脸。原后续专业算法和竞品方案继续见 `creative-production-quality.md` 与 `creative-expansion.md`。

## 逐屏设计与模型主体的进一步验收

实际查看[稿定详情页缩略图](https://www.gaoding.com/templates/xiangqingye)和[女包完整案例](https://www.gaoding.com/editor/design?id=91592)：商品与文字并非固定在同一位置，满版穿搭摄影、非对称拼版、微距和窄说明区形成节奏。牛轧糖、五金、香水、米饭和水果模板使用不同的商品占比、裁切、标题方向与信息密度。[Amazon 官方 A+ 展示](https://sell.amazon.com/tools/a-content)用于核对生活场景、热点和对比模块；本次未完成具体 ASIN 的整套商品图对比。花瓣、创客贴访问验证阻断，未算入已完成对照，也未复制模板素材。

固定标题区、固定栏目头和重策划仍锁旧创意，分别存在于排字坐标、前端策划与服务端 KB20 知识、卖家视角补充提示中。现已贯通逐屏构图和导出坐标，统一品牌识别但变化文字位置、字号与裁切；重新策划保留事实与用户约束，要求换具体场景或摄影手法。

真实儿童镜架样图已分别呈现人物场景和静物，文案仍需审校，静物图保留了旧方案的一部分视觉元素。两张样图只能证明生成与布局变化可用，不能证明达到了各平台的成品设计要求。后续按同一商品比较至少三个创意方向，逐项核对商品轮廓、标识、文字正确性、手机缩略图可读性与成套节奏；用服饰、食品和家居素材补齐品类验证。不能只用构图种类数量判断设计品质。

室内默认以模型为主体，新建、局部调整、知识和历史互斥展开；方案不完整时保留“方案需核对”入口。知识库在后台直接可见，新建与局部对话均检索知识并保存引用。当前是按范围、空间、风格和文本检索的专业条目库，不能据此称为已完成文档上传、向量检索与施工级知识管理。
